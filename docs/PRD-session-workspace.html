会话与工作位置

让用户不必先想「在哪儿工作」，也永远知道 agent 正在哪儿动手。本方案重新定义会话、目录与左栏归属之间的关系。

00摘要与决策

一句话：会话是「做什么」，工作位置是「在哪儿做」。位置在落库时确定，之后只读；选错了就用「在新位置继续」复制一条会话过去。默认空间是容器：每条会话有自己的产物目录；P0 不做空间级共享记忆，但产物必须随时找得到。

四条核心决策

  1. 新建会话不选目录，落在一个「默认空间」。所有没有指定目录的会话都落在这里；每条会话在落库时获得自己的产物目录，同名文件不会互相覆盖。默认空间在 P0 不共享记忆，只承担落点与容器。
  2. 只有地点，没有「会话类型」。左栏按地点分区：默认空间与工作目录。路径不是身份，但随时可查（产物清单、「打开此会话的位置」、审批卡「查看位置」）。
  3. 位置创建后只读。想换地方，用「在新位置继续」把对话与改动记录复制到目标位置；原会话与文件不变，旧工具卡仍按执行时的根打开旧文件。
  4. 产物不打折。每条会话有产物清单；默认空间有跨会话产物清单，含已删除会话；默认空间删除会话时冻结 manifest 并保留目录；工作目录删除会话只保留文件、不保留按会话的线索（如实写明）；移除目录只隐藏、可恢复；默认空间不可移除。
本方案不采用「开局选模式」

不把「工作模式 / 代码模式」做成创建会话时的二选一。模式是结果，不是前提：用户可以聊着聊着才决定把会话接到一个仓库，也可以一开始就指定目录。把可变的归属做成开局的开关，会增加一次不必要的决策；而「落库后位置只读」又保证了运行时不会被中途改动。理由见 3.1。

01背景与问题

当前产品把「目录」同时当成三样东西：会话的归属、agent 的执行边界、左栏的分区依据。三者耦合后，用户看到的是一组彼此矛盾的行为。

观察到的行为用户此刻的想法造成的后果
顶部「新建会话」总是进「任务」栏，只有在某个项目行上点「+」才会进该项目。 「我明明在项目里，为什么新会话跑到任务里去了？」 会话建错地方，用户回左栏找不到它。
任务会话在会话头和起手区显示形如 ~/.colt/tasks/… 的路径（落库后还会带上时间戳子目录）。 「这是什么？我什么时候选过这个目录？」 路径变成噪音；用户无法从中判断 agent 在哪儿动手。
起手区把目录摆在显眼位置，且第一条消息发出后目录不能再改。 「我开始时没想清楚，现在只能重开一条会话。」 已经积累的上下文与对话被迫丢弃。
不指定目录的会话产生的文件没有可识别的入口。 「它刚才写的文件去哪了？我能不能看？」 用户不敢让 agent 写文件，或事后找不到产物。
移除一个项目会连它名下所有会话记录一起删除。 「我只是不想在左栏看到它，没想删掉对话。」 不可恢复的对话丢失，信任受损。
文件夹被移动、改名或所在磁盘断开后，会话仍显示旧路径。 「它到底在哪儿跑？为什么还能发消息？」 失败不可见；agent 可能在错误的位置执行。
「任务 / 项目 / 空间」三个词在界面与文案里交替出现。 「这仨是一个东西吗？」 用户需要先学会产品内部的行话，才能找到自己的会话。

问题本质

目录是 agent 的执行边界，但不该是创建会话的门槛。用户开始一件事时想的是「我要做什么」，而不是「我要在哪个文件夹里做」。产品却把后者前置成了必答题，还把它显示成一个用户从未选择过的路径。

位置应当稳定，纠错应当保上下文。位置一旦落库就不再原地改动，避免界面与运行时各说一套；选错位置的真实代价应该是一次「把对话复制到新位置」，而不是重开会话、丢掉上下文。删除一条会话也不该让用户担心「文件是不是也没了」。

目标（以可观察的行为描述）

  • 用户第一次打开应用就能直接输入，全程不需要做出任何目录决策。
  • 任意一条会话，用户都能在同一处看到它的工作位置，并在发送前知道 agent 的操作范围。
  • 选错位置时，用户能把当前对话复制到正确位置继续，原会话与已经产生的文件都不受影响。
  • 删除会话、移除工作目录都不会误删文件；移除目录不会默认销毁对话记录。
  • 目录不可用时，用户能看到明确原因和恢复动作，而不是一条指向不存在路径的会话。

02范围与用户场景

最小完整旅程（P0）

  1. 首次打开应用，中间区直接是输入框；用户发出第一条消息。
  2. 该会话出现在左栏「默认空间」分区——所有不指定目录的会话都落在这里；它拥有自己的产物目录。
  3. 用户意识到要在这个仓库里改代码，在会话菜单里点「在新位置继续…」，选择该仓库。
  4. 产品新建一条会话：对话与改动记录复制到当前尖端，落在该目录下；原会话留在默认空间。旧工具卡仍指向旧文件，文件本身不复制。
  5. 几天后该文件夹被移动，新会话提示「位置不可用」，用户点「重新定位…」选中新位置后继续。

完成证据：新会话位于左栏该目录之下，原会话仍在默认空间；两边历史完整；重启后位置不变；「打开此会话的位置」分别进入各自的产物目录；默认空间的跨会话产物清单能找到两边碰过的文件，包括已删除会话的文件。

03产品模型

用四个对象解释归属，再加一个产物视图：会话、工作位置、默认空间、工作目录、产物清单。前四个决定「在哪儿做」，最后一个回答「东西在哪」。

对象用户视角的定义例子
会话 一次协作的完整记录：说过的话、agent 做过的动作、等待过的授权、产生的历史。 「修登录超时」这条会话。
工作位置 这条会话「在哪儿动手」，在落库时确定，之后只读。只有两种：默认空间，或某个工作目录。 默认空间；或「在 colt 目录中工作」。
默认空间 应用自带的容器：所有未指定目录的会话都落在这里；每条会话有自己的产物目录，文件不会互相覆盖。P0 不共享空间级记忆。 左栏的一行「默认空间」，展开是这些会话。
产物目录 agent 读写文件的地方。默认空间的会话各自一个子目录；工作目录的会话就是该目录。 默认空间里的一个会话子目录。
产物清单 按会话列出产物文件的产品内视图。默认空间的清单跨会话，包含正常、归档与已删除会话的目录。 「产物」入口；会话菜单里的「查看产物」。
工作目录 用户自己打开、并登记在左栏的文件夹。它既是其下会话的共享目录，也是它们的产物目录。 E:\code\opensource\colt

用户与触发

主要用户：在本机使用 agent 做开发、排查、脚本与文档工作的个人用户。他们既会「随手问一句」，也会「在一个仓库里连续干几天」。

触发：用户想开始一件事，但还没决定这件事是否要落到某个目录里。

完成条件：用户能在不中断协作的前提下，把对话带到正确的位置继续，并始终知道 agent 的操作范围。

3.1 为什么不在开局让用户选「模式」

把工作分成「工作模式 / 代码模式」看起来清晰，但它把一段可能持续很久的协作压缩成了一个开局开关。真实情况是：

  • 用户常在会话进行中才决定「要不要把这个结果落到某个仓库」。
  • 用户常在开始时并不确定最终要动哪个目录。
  • 「先随便聊聊，聊着聊着要改代码」不是例外，而是最常见的过程。

因此本方案不设模式选择器：不指定目录就落在默认空间，选择目录就进入工作目录；左栏按「位置」分组，而不是按「模式」分组。位置在草稿期可以改，落库后只读——这样既不需要开局问一次，也不会在运行中把根换掉。

代价是用户需要理解两个动作：草稿期「选择工作位置」，落库后「在新位置继续」。前者用位置 chip 偿还，后者用会话菜单里的一个动作偿还；比在开局多问一个问题、再在意图变化时逼用户重开会话更划算。

3.2 默认空间：容器与产物

默认空间要解决两件事：开始时不要求选目录；不同工作的文件不要互相覆盖。做法是容器 + 隔离产物；空间级共享记忆不做，放 P1。

默认空间工作目录
共享什么只共享容器与左栏分区；不共享记忆共享目录内的文件与目录级约定
产物目录每条会话一个私有子目录目录本身
记忆 / 约定每条会话按自己的产物目录加载；用户级偏好生效按该目录加载；同目录会话共享

为什么先不做共享记忆：一旦空间级记忆可被任一会话写入，就要回答「谁写的、写到哪、怎么撤销、会不会污染其他会话」。这些问题比产物隔离更贵，也更难向用户解释；P0 先把产物做扎实，记忆共享放 P1。

代价是跨会话的文件连续性没有：新会话看不到上一条会话写的文件。产品用产物清单偿还——每条会话的清单按目录内容列出文件，默认空间再提供跨会话清单（用户可查，agent 读不到别的会话的目录）；需要连续时，用「在新位置继续」带着对话过去，或显式复制文件。

「默认」描述的是没有指定目录时的落点，不是寿命短，也不是低优先级。一条落在默认空间的会话可以连续用上一周。

3.3 为什么路径不作为主标签

路径只有在它是用户选择的结果时才有信息量。把系统路径当成会话的标题，会制造三个误解：「我需要管理这个目录」「这是一个项目」「换个会话就要换个目录」。

因此界面用空间名做主标签，路径退到次要位置，但不是永远不出现：

  • 工作目录行展开或悬停时显示完整路径；
  • 默认空间的「产物」入口打开跨会话产物清单，按会话列出文件；会话菜单的「打开此会话的位置」直达当前会话的产物目录；
  • 审批卡提供「查看位置」，展开后显示这条会话的产物目录——这是用户核对操作范围的关键时刻，不能用一句「默认空间」糊弄过去。

原则是：路径不是身份，但必须随时可查。

3.4 存量会话与旧目录

升级后用户最先问的是「我原来的会话去哪了」。一次性的过渡规则如下：

  • 旧「任务」项目及其会话归入左栏的「默认空间」，不再单独占一个项目行。
  • 旧会话本来就有自己的时间戳目录，正好成为它的产物目录；文件不搬移。打开这些旧会话时，「打开此会话的位置」指向它原来的目录。
  • 新的默认空间会话在默认空间容器下各自分配一个子目录；不会落进旧的共享时间戳目录。
  • 旧「项目」→ 工作目录，名称、路径与旗下会话保持不变。
  • 记忆不迁移：旧会话目录里的说明文件与记忆继续按该目录加载；P0 不做空间级共享记忆，所以不需要把旧记忆汇入一个共享空间。
  • 旧已删除会话的目录如果还在，产物清单会把它列为「未关联目录」，按目录名中的时间与短 id 识别；有 manifest 的按 manifest 显示标题。
  • 升级后给一次非阻塞说明，告知会话已归入默认空间或工作目录；不弹必须处理的对话框。

Assumption 旧时间戳目录里的文件默认不整理、不迁移。是否提供「把旧会话文件收进默认空间」的用户主动操作，见 开放问题。

  • 顶部入口不「继承」一个不存在的位置：当前在默认空间时，新建的仍在默认空间。
  • 顶部入口不允许静默跟随：按钮上必须能看到这次会落到哪里，避免用户在 colt 会话里点新建、却不知道会话已经进了 colt。
  • 当前会话所属目录已不可用时，不把新会话建进去；提示重新定位，或在别处继续。

FR-02

默认空间

默认空间是一个容器：所有不指定目录的会话都落在这里，每条会话有自己的产物目录。P0 不做空间级共享记忆，只把产物做扎实：每会话产物清单、跨会话清单（含已删除会话）、目录 manifest。这里的「默认」指没有指定目录时的落点，不指寿命短或优先级低。

触发
使用「新建会话」且当前没有目录上下文，或从「默认空间」分区头新建。首次启动时的第一条会话也落在这里。
处理规则
  • 所有没有指定目录的会话都落在默认空间，不要求用户选目录。
  • 每条默认空间的会话各有一个私有产物目录，落库时分配并写入 manifest。同名文件不会互相覆盖。
  • P0 不共享空间级记忆：每条会话按自己的产物目录加载说明文件与记忆；用户级偏好仍然生效。空间级共享记忆放 P1。
  • 默认空间是持久容器，不是缓存：不做自动清理，不因会话结束而回收。
  • 界面不展示默认空间的路径。会话头与位置 chip 只显示「默认空间」；会话菜单提供「打开此会话的位置」，直接进入该会话的产物目录。
  • 默认空间分区提供「产物」入口，打开跨会话产物清单：按会话分组，包含正常、归档与已删除会话；每行显示标题、时间与目录里的文件，可打开文件或位置。支持按标题、时间与文件名查找；「在文件夹中打开」只作为兜底。
  • 清单口径以目录内容为准：清单列出产物目录里实际存在的文件，按修改时间排序；改动记录只用来标注「哪条会话记录过这个文件」，不作为清单的唯一来源。这样 agent 通过命令行写入、外部程序产出、用户自己放进去的文件都能出现，不会出现「磁盘里有、清单里没有」。
  • 清单不承诺「只列 agent 写过的文件」，也不承诺目录被外部改动后立即刷新：打开清单时重读目录，并提供刷新动作。
  • 产物目录名是内部标识（时间 + 短 id），展示标题以 manifest 为准，不承诺目录名等于「时间 + 标题」。
  • manifest 生命周期：落库时创建（标题、创建时间），标题随会话更新；删除时补写文件列表并冻结。清单以目录内容为准，manifest 的文件列表只在目录不可读时兜底。
  • 默认空间不可移除，界面不提供「移除」；它是所有未指定目录会话的保底落点。
结果与状态
会话归属「默认空间」，拥有独立产物目录与 manifest；产物清单可打开；可在别处「在新位置继续」，或按 FR-07 归档、删除。
异常
  • 默认空间无法初始化（磁盘满、无权限）：不创建会话，显示真实原因；提供「重试」与「选择工作位置…」。这是唯一要求用户选择工作目录的例外。
  • 某条会话的产物目录被外部删除：会话仍可查看历史；下一次发送前提示「位置不可用」，提供「重建此会话的产物目录（保留对话）」与「在新位置继续…」；产物清单标记「目录缺失」。
  • 默认空间容器整体不可用：已存在会话只读；提供「重建默认空间」与「选择工作位置…」。重建只为在册会话补缺失的产物目录（磁盘上还在的不动），不恢复已删除会话的目录。
  • 删除会话时 manifest 写入失败：删除继续，产物清单按目录内容显示，并标记「缺少 manifest」；不因此阻断删除。
产物怎么找回来

当前会话：工具卡里的路径、会话菜单「查看产物」和「打开此会话的位置」。其他会话：默认空间的「产物」清单按会话分组，支持按标题、时间与文件名查找。会话已删除：目录与文件仍在，manifest 保留标题与文件列表，产物清单继续列出它；旧版本的无 manifest 目录显示为「未关联目录」。

不显示路径，不等于没有边界

默认空间的审批卡写明「范围：默认空间 · 本会话」，并提供「查看位置」：展开后显示这条会话的产物目录。用户可以不知道路径，但必须能在关键时刻核对 agent 的操作范围——它只在这条会话的产物目录里，不会伸到其他默认空间会话，更不会伸到整个磁盘。

为什么 P0 不做共享记忆

共享记忆需要回答「谁写的、写到哪、怎么撤销、会不会污染其他会话」。这些问题比产物隔离更贵。P0 先把产物清单与 manifest 做扎实；空间级共享记忆作为 P1，届时再补写入审批与可见性。

FR-03

在新位置继续

选错位置的纠错成本应该是一次复制，而不是重开一条会话。产品不复用「原地切换」：目标位置确定后，复制一条带完整对话的新会话过去，原会话保持原样。

触发
  • 会话菜单：「在新位置继续…」。
  • 会话头位置 chip 菜单：同一条动作；已保存会话不提供「切换」或「移到默认空间」。
  • 草稿期改位置不走本流程，见 5.4。
可用条件
会话已保存、不在运行中，也不在等待授权或等待回答。运行中入口置灰，并说明「运行中的会话不能复制到新位置，请先停止」。
处理规则
  • 先列出已登记的工作目录，再给「选择其他文件夹…」；目标为默认空间时是一个独立选项「默认空间」。
  • 选择已登记的目录：直接使用，不新增重复行。
  • 选择与当前相同的位置：不产生任何变化，确认按钮置灰。
  • 确认后新建一条会话：复制源会话到当前尖端，标题沿用并加「（续）」（已以「（续）」结尾时不重复追加），落在目标位置；打开新会话，源会话保持不变。
  • 目标为默认空间时，先为新会话分配它自己的产物目录，再以该目录作为运行时根创建会话；新会话不存在「没有根」的中间状态。目标为工作目录时，产物目录就是该目录。
  • 对话与改动记录一起复制：应用侧的改动记录连同执行时的根（root_path）与净值复制到新会话；不复制文件基线，新改动在目标位置重新建立基线。
  • 不移动、不复制磁盘上的文件；不改源会话的标题、位置与历史。
  • 旧工具卡仍按执行时的根解析旧路径，旧文件仍可打开；文件已不存在时如实报告失败，不静默跳过。
  • 复制需要先冻结源会话的运行时（停掉源会话的执行进程、等它退出）再复制历史。复制期间源会话只读，不能发送消息；完成后重新打开源会话即可继续，不需要用户做额外操作。界面必须写明「复制期间源会话暂时只读」。
  • 复制期间显示不确定进度（「正在复制对话…」），不承诺百分比，不阻塞其他会话；大历史可能需要等待。失败时源会话不受影响，未完成的新会话不留下。
  • 草稿没有历史，不走本流程；输入框里未发送的内容与附件不在历史中，不会被复制。

示例

「排查登录超时」在默认空间聊了 6 轮，agent 写了一份 notes.md。用户选择「在新位置继续…」并选中工作目录「colt」后：

  • 新建「排查登录超时（续）」，位于左栏 colt 之下，对话与改动记录复制到第 6 轮；
  • 新会话里读写、审批范围都在 colt；原会话仍在默认空间，notes.md 也还在它自己的产物目录，并在产物清单里可见；
  • 复制过去的工具卡仍按执行时的根解析旧路径，旧文件可打开；文件本身不复制；需要把文件带过来时，由用户或 agent 显式复制。
确认框必须包含
在新位置继续的确认文案

「会新建一条会话，把当前对话与改动记录复制到「目录名」继续；原会话保持原样。文件不会复制，旧文件仍在原位置，旧工具卡仍可打开。复制期间原会话暂时只读，完成后可以继续。新会话按目标目录加载它自己的约定与记忆。」

目标为默认空间时，首句改为「把当前对话与改动记录复制到默认空间继续」，并说明会为新会话分配一个独立的产物目录与 manifest。

结果与状态
源会话数据不变；复制期间源会话只读，完成后可继续。新会话出现在目标位置，对话与改动记录完整，位置固定。左栏同时保留两条会话；重启后保持。
异常
  • 目标目录不可用：不能确认，提示先重新定位或换一个目录。
  • 目标是一个文件而不是文件夹：拒绝并说明「请选择一个文件夹」。
  • 复制过程中目标目录被移除或磁盘断开：不创建新会话，源会话保持不变，说明原因。
  • 复制失败或空间不足：清理未完成的新会话，源会话不受影响。
  • 源会话已归档或所在目录已移除：只要历史可读就允许复制；源位置不可用时明确提示旧文件可能打不开。
  • 改动记录复制失败：对话仍复制，新会话标记「旧改动记录未复制」，不阻断创建。
  • 历史里引用的旧文件已不存在：工具卡按原位置显示并如实报告失败，不静默跳过。
  • 输入框里有未发送的内容或附件：不复制，并在确认框里说明。
为什么是复制，不是原地切换

原地切换要在一个已经运行的会话上换掉根：worker 要重启，审批、记忆、技能都要重新注册，界面显示新位置而运行时还在旧位置的风险始终存在。复制则让新会话从第一条消息起就长在目标位置，没有半途状态；源会话也保留了当时的工作现场，事后可对照。

FR-04

工作目录的登记与识别

让用户自己选择的目录成为一等公民：可识别、可纠正、不可用时有出路。

打开工作目录
  • 选择任意已存在的文件夹。
  • 已登记过的目录直接选中，不产生重复行；若它处于「已移除」，打开同一路径即恢复。
  • 不要求是 Git 仓库；不是仓库时不显示分支，也不提示错误。
产物目录
工作目录下的会话不另建子目录：该目录本身就是共享目录与产物目录。同一目录下的多条会话共享目录级约定，也共享同一批文件。
产物清单
会话里的「查看产物」按目录内容列出文件（改动记录标注哪些由该会话记录过），可打开文件或「在文件夹中打开」；不另设目录级产物清单。删除会话后文件仍在目录里，但产品不再提供「这条会话碰过哪些文件」的线索。
命名与区分
  • 左栏行以文件夹名为显示名。
  • 展开目录行或悬停显示完整路径。
  • 两个目录同名时，在名字旁显示父目录名以区分。
  • 允许登记子目录；同样用完整路径区分层级。Assumption, TBD
可用性检查
在应用启动、打开会话、发送消息前各检查一次。检查结果决定目录行与会话是否可运行。检查异步执行、带超时、不阻塞界面：网络盘或已断开的移动盘超时后按「不可用」处理，并允许用户点「重试」；启动时先显示上次已知状态，检查完成后再更新。处于「已移除」的目录不参与检查，也不检查其下会话。
不可用时
  • 目录行标记「位置不可用」。
  • 其下会话可以打开并查看历史，但不能发送。
  • 会话头显示横幅，给出两个动作：「重新定位…」「在新位置继续…」。
已移除时
  • 目录行从左栏「工作目录」区收进底部「已移除」区，其下会话一并收起。
  • 不删除登记、不删除磁盘文件夹、不删除会话记录。
  • 恢复到「工作目录」区时，重新做一次可用性检查：可用则正常显示，不可用则标「位置不可用」。
  • 若同一路径此前已被重新打开，恢复时合并到那一行，不产生重复行。
重新定位
这是修复同一个工作目录的登记，不是给单条会话换位置：选择新文件夹后确认（历史保留、文件不搬移），更新目录登记；其下所有会话（含归档与已移除）按登记自动跟随，不逐条改路径。若新目录已有登记，提示将合并到已存在的目录行。运行中的会话需先停止，再重新定位。
重命名显示名
P1 只修改左栏显示名，不修改磁盘文件夹名。
结果
目录行状态与真实可用性一致；任何失败都能被用户看见并恢复。

默认收起，标题带数量；展开只列目录名与「恢复」，并注明「恢复后其下会话一起回来」。已移除目录不参与运行；搜索命中时仍显示其会话，并标记「已移除」。
高亮
当前会话所属的目录行与会话行高亮；切换会话时高亮跟随；默认空间分区在其中的会话被选中时同样有标记。
搜索
匹配会话标题、位置名称（默认空间 / 工作目录名）、完整路径与产物文件名；归档与已移除的会话也参与搜索，并在结果里标出状态。不搜索对话正文——这是已明确的限制，见开放问题。
空态
  • 没有默认空间会话：「不指定目录的会话会出现在这里，每条都有自己的产物目录」。
  • 没有工作目录：「还没有工作目录，打开一个文件夹开始」。
  • 没有已移除目录：整个分区不显示。
  • 搜索无结果：如实显示没有匹配，不展示空白区。
已归档
跨位置汇总，默认收起；每行标出它所属的工作位置；可恢复。
窄屏
位置 chip 与状态标签换行显示，不截断、不隐藏；宁可占两行，也不让用户看不到自己在哪儿。

FR-07

移除、删除与归档

让「收拾」不产生意外损失：对话与文件各有各的边界；「不想看到」与「想销毁」是两件事。

归档会话
从常规列表收进底部「已归档」区，数据完整保留，可恢复。运行中不能归档。
删除会话
  • 确认框写明：「只删除对话与记录，不删除磁盘上的文件。默认空间的目录留有 manifest 可再找回；工作目录的文件仍在原目录。」
  • 同时显示它的工作位置，并提供「查看产物」「打开此会话的位置」；默认空间的会话打开它自己的产物目录。
  • 删除时在 manifest 补写文件列表并冻结；产物目录与文件保留，产物清单继续列出它。
  • 运行中不能删除，入口置灰并说明原因。
删除后的产物
会话记录消失，产物目录与文件保留。默认空间的目录继续出现在「产物」清单里，按 manifest 显示标题、时间与文件；旧版本没有 manifest 的目录显示为「未关联目录」。工作目录下的文件同样不受影响，但文件混在共享目录里，产品不再提供「这条会话碰过哪些文件」的线索——这是两类位置的不对称，如实保留。
从列表移除工作目录

只有一个动作：仅从列表移除。目录行与其下会话收进左栏「已移除」区；磁盘不动；随时可「恢复」，重新打开同一文件夹也会自动恢复。P0 不提供「同时删除这里的会话记录」——删除会话是单条会话的动作，避免一次误操作销毁一批对话。

任一相关会话在运行中（含等待授权 / 等待回答）时，整次移除被拒绝，并说明是哪条会话。

恢复被移除的目录
  • 在「已移除」区点「恢复」，目录与其下会话一起回到「工作目录」区。
  • 恢复时重新检查可用性；不可用则标记「位置不可用」，会话只读，直到重新定位。
  • 若同一路径已被重新打开，直接合并到那一行，不产生重复行。
默认空间
不可移除，界面不提供「移除」；也没有「已移除」状态。它承担所有未指定目录会话的落点，不能留空。
删除文件夹
产品不执行。用户在系统里操作后，目录行变为「位置不可用」，会话可查看、不可发送。
与「清空重来」的区别
首启的「清空重来」是唯一会删除全部数据与目录的入口；本节的移除只针对单个目录，且默认保留会话。
移除目录的确认文案

「将把「colt」从列表移除，并收进「已移除」。磁盘上的文件夹与其中的文件不会被删除。这里的 12 条会话会一并收起，随时可以恢复；不会删除任何会话记录。」

FR-08

安全与边界

用户不需要懂实现，也能在每一次操作前判断「它现在能碰什么」。

审批范围
每张审批卡必须写明本次操作的工作位置：默认空间的会话写「范围：默认空间 · 本会话」，工作目录里的会话写「范围：目录名」。两者都提供「查看位置」；默认空间展开后显示这条会话的产物目录，工作目录展开后显示该目录。
共享范围
  • 同一工作目录下的会话共享：目录级说明文件、目录级技能、项目记忆；它们也共享同一个产物目录。
  • 默认空间在 P0 不共享空间级记忆：每条会话按自己的产物目录加载说明文件与记忆；用户级偏好对所有会话生效。空间级共享记忆放 P1。
  • 产物不共享：每条默认空间会话有自己的产物目录，默认读不到另一条会话的文件；要读取需显式路径并走越界审批。
  • 默认空间不加载任何工作目录的目录级约定；工作目录也不加载其他目录的约定。
  • 默认空间的约定查找截止于容器根：会话按自己的产物目录加载，向上查找不越过容器根；容器根及其上层目录里的目录级约定文件（如 AGENTS.md）不参与加载，容器内也不放置这类文件。否则「不共享」会被父目录里的一份约定悄悄破坏。
空间级记忆（P1）
P0 不提供空间级共享记忆，也不提供「记住到默认空间」这类写入动作。P1 开放时必须同时给出写入审批、写入内容预览与撤销入口，避免单条会话污染整个空间。
复制会话后的边界
「在新位置继续」生成的新会话按目标目录加载约定与记忆；复制过来的历史保留旧工具卡的执行时根，界面可以打开旧文件，但这只是历史查看，不授予新会话 agent 读取旧位置的权限。agent 要读旧文件，仍按越界操作审批。
越界操作
任何跨出当前产物目录的文件操作，按高风险处理，需要用户明确授权；不存在「因为以前放行过就默认可以」的跨位置规则。用户在产物清单里打开、定位文件是用户自己的动作，不受越界审批限制；这也不会让 agent 获得读取该文件的权限。
不可用即停
工作位置不可用时禁止发送。不允许 agent 在一个不存在、已移除或未知的目录里继续执行。
移除登记后的会话
不能运行；在「已移除」区点「恢复」后，按可用性检查决定是否可发送。
删除会话后的产物
产物目录与文件仍在，产物清单可打开；但已删除会话不再有 agent 运行时，不存在「从已删除会话继续执行」的入口。

05共享规则

5.1 六条硬规则

路径不是身份，但随时可查

默认空间的绝对路径只出现在「默认空间产物」「打开此会话的位置」「查看位置」与系统对话框里，不作为主界面的标题、副标题或正文；工作目录展开或悬停时显示完整路径。

不替用户删文件

删除会话、移除目录、删除登记，都不删除磁盘上的文件；默认空间的产物目录也不随会话删除而删除。默认空间不可移除。唯一会删除目录的操作是首启的「清空重来」，且它必须在独立确认中出现。

不在不可用的位置里运行

目录不存在、无权限、磁盘断开或已被移除时，会话只读。用户必须显式重新定位、恢复目录，或在别处继续，才能继续发送。

位置落库后只读

已保存会话的工作位置不由「原地切换」改变；要换位置，用「在新位置继续」复制一条新会话。这样界面显示的位置与 agent 实际执行的根不会分叉。

产物隔离，但必须可查

默认空间每条会话都有自己的产物目录，工作目录内的会话共享同一个目录；两类位置之间不共享文件。清单以目录里的实际文件为准，改动记录负责标注归属。默认空间提供每会话清单与跨会话清单（含已删除会话），删除时冻结 manifest 保住线索；工作目录删除会话后不保留按会话的线索，文件仍按路径可浏览。旧路径一律按执行时根解析。

P0 不做空间级共享记忆

默认空间只共享容器与左栏分区；说明文件与记忆按每条会话自己的产物目录加载，用户级偏好对所有会话生效。空间级共享记忆与「记住到默认空间」放 P1，避免在 P0 引入写入权限与污染问题。

复制会话失败（空间不足 / 目标断开） 不创建新会话，源会话保持不变；清理未完成的记录。 真实原因 +「重试」；源会话可继续使用。
复制历史很大，耗时较长 显示不确定进度；不阻塞其他会话；完成后自动打开新会话。 「正在复制对话…」；不承诺百分比，大历史需要等待。
默认空间里某条会话的产物目录被外部删除 会话只读；提供「重建此会话的产物目录（保留对话）」与「在新位置继续…」。 「这条会话的产物目录不存在」+ 两个动作。
删除默认空间会话后想找产物 产物目录与文件保留；在「产物」清单里按 manifest 的标题与时间定位；旧版本无 manifest 的目录显示为「未关联目录」。 目录仍存在，标题、创建时间与文件列表可识别。
删除工作目录下的会话后想找它碰过的文件 文件不动；产品不保留按会话的线索，需按文件路径在目录里找。 会话记录消失，目录里的文件仍在。
复制过程中源会话要发消息 复制期间源会话只读；发送入口置灰并说明「复制完成后可继续」，不做排队。 「正在复制对话，完成后可以继续」。
归档会话所在目录被移除或不可用 归档区仍能看到；打开时提示「已移除」或「位置不可用」，并提供对应恢复动作。 归档行标出所属位置与当前状态。
系统拒绝「在文件夹中打开」 如实提示失败，不假装已打开。 「无法打开文件夹」+ 原因。

07设计取舍记录

记录被否掉的备选，避免评审时重复讨论。

备选方案结论理由
新建时让用户选「工作模式 / 代码模式」不做把可变的归属做成开局开关；见 3.1。
每条不指定目录的会话一个独立隐藏空间（v0.3 方案）不采用产物不可见、删除会话后难找回；改为「容器 + 每会话产物目录 + 产物清单」。
默认空间完全共享，文件也共享（v0.4 方案）不采用不相关的工作会互相覆盖；改为「容器 + 隔离产物」。
默认空间共享空间级记忆（v0.5 方案）P0 不做，放 P1共享记忆要解决写入权限、污染与可见性，成本高于产物隔离；P0 先把产物做扎实，见 3.2 与 FR-08。
默认空间也显示绝对路径不做系统代管的路径没有决策价值，只会制造「需要管理它」的误解；但保留「默认空间产物」「打开此会话的位置」与「查看位置」。
默认空间允许移除不做它承担所有未指定目录会话的落点，移除后没有保底位置。
落库后原地切换工作位置不做（P0）切换要换掉运行时的根：worker 重启、审批与说明重注册，容易出现「界面已切、运行时没切」；改为复制会话，见 FR-03。
复用现有分叉实现「在新位置继续」采用已有「库快照 + 新对话 + 新会话行」的能力；只需让新会话落在目标位置，并把改动记录连同执行时根复制过去。
复制只带对话，不带改动记录不采用用户明确要求产物不打折；副本必须保留旧改动记录与旧工具卡路径，否则「在新位置继续」会丢掉产物线索。
复制后的旧工具卡只读、不能打开旧文件不采用产物不打折；旧工具卡按执行时的根解析，旧文件仍可打开；不存在时如实报错。
目录名用「时间 + 标题」不采用落库时标题还不存在；改为内部「时间 + 短 id」，产品用 manifest 展示标题，不随标题改名。
默认空间产物清单放 P1不采用「产物找得到」是原始痛点；P0 必须提供每会话清单与跨会话清单（含已删除会话）。
产物清单只以改动记录为来源不采用命令行写入、外部程序产出、用户自己放进去的文件会漏，出现「磁盘里有、清单里没有」；改为以目录内容为准，改动记录只标注归属。
工作目录下删除会话后保留按会话的线索不采用需要额外的快照存储与目录级清单入口，超出 P0；只保留文件，删除后不再提供按会话的线索，并如实写明。
默认空间不可用时再提供一个兜底落点（临时工作区）不采用会多一个用户无法感知的根，并带出产物归属、可发现性与清理问题；P0 直接如实报错并要求选目录，作为唯一例外。
移除目录时提供「同时删除全部会话」P0 不提供避免一次误操作销毁一批对话；删除会话是单条动作，移除目录只隐藏。
移除的目录直接消失改为进入「已移除」区用户可能只是清理左栏；需要一条可见的回头路，而不是靠「重新打开同一文件夹」猜。
用「项目 / 空间」命名目录改为「工作目录」用户需要先解释的词不适合做主导航；「工作目录」是字面意思。
打开目录时自动初始化仓库或文件不做产品不为用户写代码目录；没有需求支撑的副作用。
复制会话时自动把旧文件搬到新位置不做会产生两份真相或不可逆的移动；需要时由用户或 agent 显式复制。
复制时显示精确进度条不做（P0）实现需要额外的事件通道；P0 只显示不确定进度，不承诺百分比。

08开放问题

问题影响当前处理
默认空间产物的清理与占用 每条默认空间会话都有自己的产物目录，删除会话也不删目录，长期会累积；用户可能不知道它有多大。 TBD 默认长期保留，不做自动清理。P0 已提供跨会话产物清单；P1 再做占用展示与用户主动清理。
产物清单的筛选、排序与占用 会话与文件多了以后，按标题、时间、文件名查找还不够；需要按目录、状态与大小筛选。 P0 提供按会话分组、标题/时间/文件名查找，含已删除会话。P1 增加筛选、排序与占用。
是否需要空间级共享记忆 P0 默认空间不共享记忆，某条会话的约定无法自动带到下一条；用户可能希望「记住到默认空间」。 P1 开放空间级共享记忆，同时提供写入审批、内容预览与撤销；P0 不增加「记在哪一层」的选择成本。
默认空间是否需要「命名空间 / 分组」 产物已经按会话隔离，剩下的问题是左栏列表的组织；不相关的非代码任务仍会挤在同一分区。 P1 提供「新建命名空间」，为某个项目单独开一个默认空间；P0 只保留「在新位置继续」到工作目录这一个隔离出口。
未来是否提供原位切换工作位置 复制会产生第二条会话；有些用户可能只想让原会话换地方。 P1 评估 需要先解决 worker 重启、审批重注册与「界面已切、运行时没切」的一致性；P0 一律复制。
搜索是否覆盖对话正文 用户常按「我记得聊过……」来找会话，仅搜标题与位置名会漏。 TBD 已明确为当前限制；若要做，需先解决正文索引的体积与隐私边界。
工作目录显示名是否允许重命名 名字过长或同名时难区分。 P1 只改显示名，不改磁盘。
是否允许登记网络盘、可移动盘 可用性检查与错误文案。 Assumption 允许，只要能访问；不可访问时按「位置不可用」处理。
子目录是否应与父目录合并为一个工作目录 同一仓库下多个入口可能产生多行。 Assumption 不自动合并，用完整路径区分；待用户反馈。
是否需要「最近使用的工作目录」快捷入口 打开多个目录后，新建会话时定位成本上升。 TBD 可能进入 P1；当前依赖顶部入口跟随上下文。
旧时间戳目录里的文件是否收进默认空间 升级后旧会话的产物仍分散在各时间戳目录，用户可能希望统一到默认空间下。 Assumption 不自动搬移（避免大范围移动用户文件）；是否提供「用户主动收集」待评审。
大历史复制是否需要更便宜的替代 「在新位置继续」要复制整个对话库与改动记录，长会话会慢且占磁盘。 P1 评估「摘要交接」：只把压缩摘要带到新位置，成本低但会丢细节，与完整复制并存。
manifest 的格式与保留时长 删除会话后目录要能被产物清单识别；长期保留会累积，清理又会丢识别信息。 TBD P0 在目录内写 JSON manifest（生命周期见 FR-02）；保留时长与清理入口待定。
旧版本无 manifest 的目录如何识别 升级前删除的会话没有 manifest，只能按目录名与修改时间猜测。 Assumption 产物清单显示为「未关联目录」，按目录名中的时间与短 id 排序；不自动删除。

09术语表

术语定义
会话一次协作的完整记录，包含对话、工具动作、审批与历史。
工作位置会话在哪儿动手，落库时确定，之后只读；只有默认空间或某个工作目录两种。
默认空间应用自带的容器：所有不指定目录的会话都落在这里；每条会话有自己的产物目录。P0 不共享空间级记忆，不可移除。
产物目录agent 读写文件的地方。默认空间的会话各自一个子目录；工作目录的会话就是该目录。
产物清单按会话列出产物文件的产品内视图。以目录里的实际文件为准，改动记录标注归属；默认空间的清单跨会话，含正常、归档与已删除会话，旧版本无 manifest 的目录显示为「未关联目录」。
执行时根一条工具调用或改动记录发生时的产物目录。复制会话后，旧记录仍按执行时根解析，不按新位置重新解释。
manifest产物目录内的 JSON 清单：落库时创建，标题随会话更新，删除时补写文件列表并冻结（生命周期见 FR-02）；目录不可读时作清单兜底。
空间级共享记忆（P1）默认空间内跨会话共享的记忆。P0 不做；P1 开放时需同时提供写入审批、内容预览与撤销。
工作目录用户自己打开并登记在左栏的文件夹；它既是其下会话的共享目录，也是它们的产物目录。
位置不可用工作目录或产物目录在磁盘上被移动、改名、删除，或所在磁盘断开。会话只读，直到重新定位或在别处继续。
已移除工作目录被「仅从列表移除」后的状态：左栏底部可见，会话保留，可恢复；不参与运行，搜索命中时仍显示并标记状态。
在新位置继续把当前对话与改动记录复制到目标位置，新建一条会话；源会话不变，文件不复制；旧工具卡按执行时根打开旧文件。用于替代原地切换。
重新定位工作目录在磁盘上被移动后，把它重新指向新位置的恢复动作；作用于整个目录及其下会话，不是给单条会话换位置。
草稿已创建但尚未发出第一条消息的会话；只在当前窗口可见，不进左栏，位置仍可改。
