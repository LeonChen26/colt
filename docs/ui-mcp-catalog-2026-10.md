> **作用**：定 P1 内置 MCP 目录在设置页里的呈现——信息怎么分类、一屏里先说什么、动作怎么随状态变。
> **状态**：设计稿。对应实现是 `67704ae`（`feat(mcp): 内置可选安装目录`），本文是它的**呈现层重排**，主进程四层与 IPC 形状不变。

> **上位文档**：`docs/design-codewiki-integration-2026-10.md` §4 P1（纪律：默认不装 / 必须可见 / 写用户级配置要显式同意 / 卸载分两档）

---

## 一、结论

一屏里只回答三个问题：**这是什么 · 现在能不能装 · 下一步点哪**。

其余全部折叠：四行检查进「检查明细」，手动命令进同一个展开区的末尾。卡片默认高**实测 164px**（720px 内容宽，暗/亮同构）；现状把四行检查、钉版本、手动命令全铺在外面，同宽度下约 260px（估，取决于四行是否折行）。一屏能看见完整的一项，而不是半项。

## 二、现状的问题（按严重度）

| # | 问题 | 为什么严重 |
|---|---|---|
| 1 | **四连检把「前置条件」和「待安装件」当同一类说** | `codewiki` / `mcp` 在未装时必然显示「未安装 ⚠」，用户第一眼看到的是「我的机器有两处毛病」。更糟的是它的 hint 是 `pip install "codewiki @ git+https://github.com/FSoft-AI4Code/CodeWiki.git@5b95c8483b129c8f6c39f340c2ae660550967b18" "mcp<2"`——那是往**全局 Python** 里装，正好是说明句里承诺过不做的 |
| 2 | 四行常驻 + 钉版本 + 三个控件平铺 | 卡内 6 层信息同字号同权重，找不到主次；「我现在该干什么」要靠读完全部才能得出 |
| 3 | `purgeRuntime` 是设置页级 state | 它是一个**跨卡共享**的布尔值，勾一次会改掉所有卡片的卸载文案。语义上它属于「这一次卸载」，不属于页面 |
| 4 | 动作文案只有「安装 / 重新安装」 | 「运行时缺失」时按钮仍叫「重新安装」，而它实际做的是修复一个指错路径的声明——两件事被压成一个词 |
| 5 | 「钉住」那行是给工程师的 | `Python >= 3.12 · codewiki = 2.0.0 · mcp < 2` 摆在最外层，而真正有价值的 `why`（为什么必须钉）一个字都没展示 |
| 6 | 装载流水出现时卡高突变 | 用户正在看的那一项突然长高 100px，下面的内容整块位移 |

## 三、信息模型

一项 = 三类事实，各自回答一个问题：

```
① 身份   名称 · 分类 · 一句话（装了能得到什么）
② 就绪   host：这台机器必须具备的（Python / git）
         payload：安装器负责装进去的（codewiki / mcp）
③ 动作   下一步做什么（安装 / 修复 / 重新安装 / 重试）
```

**host 与 payload 必须分开，这是本稿最重要的一条。**

- `python` / `git` 缺 → **阻塞**。给结论 + 一条可执行命令 + 复制按钮。一次只说一条（缺 Python 时「codewiki 未安装」是必然的，再列就是噪音）。
- `codewiki` / `mcp` 未装 → **正常态**，显示 `+ 将装 codewiki 2.0.0 · mcp < 2`，中性色（虚线描边），不报警、不给命令。
- `codewiki` / `mcp` 已装但版本不对 → **问题**（真实场景：用户自己 `pip install -U mcp` 升到 2.x）。红 chip + 一句「重装会按钉住的版本重建依赖」。

因此 `McpProbeItem` 需要加 `kind: "host" | "payload"`。**不在渲染层按 id 硬编码**——探针以后加第五项时，硬编码就会把它默默归错组（错得很安静）。

## 四、版式

```
可选安装                                              [重新检查]
内置目录里的 MCP server……（两行内说完，含「不碰你的 Python」）

┌──────────────────────────────────────────────────────────────┐
│ [CW] CodeWiki  仓库文档生成                        ● 未安装   │  身份行
│      把仓库拆成模块树，逐页写 Markdown + Mermaid……            │
│                                                              │
│  ✓ Python 3.13.12   ✓ git 2.47.1   + 将装 codewiki 2.0.0…    │  就绪行（chips）
│  ▸ 检查明细                                                  │
│                                                              │
│  首次约 60MB · 1–3 分钟                        [ 安装 ]      │  动作行
└──────────────────────────────────────────────────────────────┘
```

- 宽度跟随设置页（`max-w-3xl`，内容区约 720），单列，不因为多一个条目就改布局。
- 卡片与「模型服务」的 ProviderCard 同构：`rounded-lg` / `border-line` / `bg-surface-raised` / `p-3`，卡间距 8。
- 字号只用三档：名称 14、一句话与按钮 12、chips 与明细 11（11.5 仅用于明细正文）。

## 五、状态与动作

| 安装状态 | 前置全过 | 前置缺件 | pill |
|---|---|---|---|
| 未安装 | **安装** | 安装（disabled）+ 阻塞条 | 灰点「未安装」/ 缺件时 warning |
| 安装中 | 进度条 + 5 步 | — | 脉动「安装中 3/5」 |
| 安装失败 | **重试** + 查看完整输出 | — | 红「安装失败」 |
| 已安装 | 重新安装 + 卸载 | + 阻塞条 | 绿「已安装」 |
| 已安装 · 版本不符 | **重新安装**（primary）+ 卸载 | + 阻塞条 | warning「已安装 · 不可用」 |
| 运行时缺失 | **修复**（primary）+ 卸载 | 修复（disabled）+ 阻塞条 | 红「运行时缺失」 |

**四种主按钮文案对应四件事**：安装＝从零装；修复＝运行时没了、声明还在；重新安装＝按钉住版本重建依赖；重试＝上一次失败了，再来一遍。

按钮**置灰不隐藏**：位置固定，用户补完 Python 回来还是点这里；旁边一句「补上 Python 后即可安装」交代原因，避免死控件感。

## 六、几个决定及理由

**D1 · 卸载确认放卡内，不用原生框。**
安装用原生 `dialog.confirm` 是对的：首次写用户级配置、范围大、后果不可见，系统对话框会被认真读一遍。卸载是回收自己刚写的那一条、可逆，而且需要用户当场做一个**带成本信息的选择**（61MB 要不要一起清）——原生框放不下 checkbox，硬拆成两问更烦。卡内确认条还能就近显示配置路径。

**D2 · 进度按「步」不按「百分比」。**
5 个可数步骤让用户判断「在动 / 卡住」；pip 的下载百分比不可靠，给假精确比不给更慌。右侧写「约 1 分钟」是量级，不是承诺。

**D3 · 失败时先说「配置未改动」。**
失败时用户最怕「装了一半，机器上多了点说不清的东西」。这句话之所以答得上，是因为安装器把写配置放在最后一步——界面该把这条设计决定说出来，而不是留在代码注释里。

**D4 · 已装态写「已对本项目生效，不必重启」。**
装完界面会主动 `mcp.reload` 当前项目。这个动作用户看不见；不写出来他就会去重启，白等一次还会觉得是我们让他等的。

**D5 · 「已安装 · 版本不符」单独一态。**
只写「已安装」会让人以为能用；只写「不可用」又丢掉「装是装过的，别去装第二遍」。

**D6 · 明细用原生 `<details>`。**
键盘可达、不需要额外状态管理，冒烟也能直接断言 `offsetParent === null` 来判断「默认收起」。

**D7 · 配置读不了时，pill 要带「状态未知」。**
现状只在区块顶部给一条 warning，卡片仍显示「未安装」——而那句话此时是**不可信的结论**（它可能只是配置文件坏了）。上限是「所有卡加后缀」，下限至少不能让「未安装」看起来像事实。

## 七、要动的实现点

| 位置 | 改动 | 规模 |
|---|---|---|
| `shared/mcp-catalog.ts` | `McpProbeItem` 加 `kind`；`McpPreset` 拆出 `category`（"仓库文档生成"），对话框文案里就只剩名字 | ~10 行 |
| `main/mcp/probe.ts` | 四项标 `kind`；载荷项未装时 `hint` 给 `null` | ~8 行 |
| `renderer/.../Settings.tsx` | 重写 `McpPresetCard`（head / chips / 阻塞条 / 展开区 / 动作行 / 流水）；`purgeRuntime` 降到卡内 | ~200 行（净增约 40） |
| `shared/protocol.ts` | 无变化（视图形状不变） | 0 |
| `smoke/modes/mcp-catalog.ts` | 四行断言改为「展开后四行」；新增「载荷项未装时无 warning 类」「默认态明细不可见（`offsetParent`）」 | ~15 行 |
| `tests/mcp-catalog.test.ts` | 补 `kind` 分组断言；`hint === null` 断言 | ~10 行 |

**两处不做就只能停在界面层的真问题**（本稿不画，因为画了就是空承诺）：

1. **安装流水存在组件 state 里** —— 切走设置页再回来，进度与 `busy` 全丢，卡片回到「未安装」，再点一次会真的重跑（主进程有单飞，不会建坏，但界面在骗人）。要兑现「离开设置页不会中断」，得把最近一次流水放到主进程（`mcp.catalog` 回带 `lastRun`，或新的 `mcp.installState`）。
2. **没有取消通道** —— `mcp.install` 没有取消接口，所以本稿不画「取消」按钮，进度态的动作行只留一句说明。

## 八、不做什么

- **不做安装向导 / 弹层**：设置页里再套一层模态，等于给「装一个东西」这件事加第二次导航。
- **不在 P1 放「生成文档」按钮**：那是 P3 的写侧，runner 还没做。点了没用的按钮比没有按钮更糟。
- **不做评分 / 下载量**：本地 stdio server，没有中心服务，这些数字只能编。
- **不做搜索框**：目录会长期只有个位数条目，搜索是负担（同右栏「+ 新增视图」菜单收掉搜索的理由）。

## 九、验收

冒烟 `COLT_SMOKE_MODE=mcp-catalog`（不打模型、不装任何东西）新增/调整：

1. 卡片默认态：`[data-mcp-card]` 在位，`[data-mcp-more]` 的内容 `offsetParent === null`（收起）。
2. 展开后四项都在（原 13 条里的四行断言改到这里，仍按 `data-mcp-probe` 取）。
3. 未安装时载荷项不含 warning/danger 色类（`data-mcp-kind="payload"` 且 `item.ok === false`）。
4. 未安装时没有「卸载」按钮、没有阻塞条（本机前置齐时）——前置不齐的情况随机器而变，**不断言**，交给单测注入。
5. `mcp.catalog` 形状不变（现有断言保留）。

单测：`kind` 分组、载荷项 `hint === null`、`purgeRuntime` 行为（卸载后运行时保留 / 清掉两条分支已在 `mcp-catalog.test.ts` 里，不需要新增）。
