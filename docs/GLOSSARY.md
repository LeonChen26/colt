# 术语与编号对照表

> **为什么需要这份文件**：仓库里的文档与冒烟用例大量使用内部编号——`⑦`、`⑦-G`、`A3-4`、`N1`、`事 B`、
> `v1.32`。**这些编号原本没有一处统一定义**，且几套编号的**形制极为相似**（`A3-4` 与 `⑦-C` 都是「大写字
> 母 + 数字」），极易张冠李戴。2026-09 的文档复核就抓到过一处真实误用：把 v1.32 的「下钻清单层」记成了
> `A3-4` 的产物。
>
> **本表只负责「这个编号指什么、在哪、还在不在」**；概念本身（净值怎么算、下钻有几层）去各自主文档看。

---

## 一、四套编号，先分清

| 形制 | 含义 | 权威定义处 | 例 |
|---|---|---|---|
| `①`~`⑦` | **界面区域编号**（七大区域） | `docs/UI-REGIONS.md` §二 | `⑦` = 右栏工作区 |
| `⑦-A`…`⑦-H` | **某区域下的规则编号**（区域号 + 字母） | `docs/UI-REGIONS.md` §二 各区域的「规则 X-Y」 | `⑦-G` = 右栏「正在处理」的规则组 |
| `A1` / `A3-4` / `B1` / `C1` | **交付批次 / 冒烟用例组编号**（无区域前缀） | `docs/NEXT-PHASE.md` §3.4、`src/main/smoke.ts` 的分节注释 | `A3-4` = 清单层那个批次 |
| `N1`~`N4` | **下一阶段计划编号**，`N` = Next | `docs/NEXT-PHASE.md` §3.1 | `N1` = 观测条目详情 |

**判断口诀**：带 `⑦` 这种圆圈数字的是**界面规则**；单独一个字母加数字的是**批次 / 用例**。

## 三、界面部件

| 叫法 | 是什么 | 在哪 |
|---|---|---|
| **Live Bar** | ⑥ 那条常驻状态条 | `Conversation/index.tsx` |
| **思考轨** | agent 推理流的独立呈现，默认整块折叠 | `MessageList.tsx` 的 `ThinkingRail` |
| **行动流** | 消息 + 工具卡 + 授权卡的合称 | `MessageList.tsx` |
| **工具卡** | 一次工具调用的卡片，可展开看入参 / 输出 / **内嵌 diff** | `MessageList.tsx` 的 `ToolCard` |
| **授权卡** | 审批卡片：四档决定 + 可见倒计时 + 风险分色 | `ApprovalCard.tsx` |
| **总账** | 「正在处理」底部那一行「N 处 · M 文件」，点它进清单层 | `FollowPanel.tsx` |
| **下钻三层** | 清单 → diff → 文件内容 | `panels/ChangeDrilldown.tsx` |
| **观测抽屉** | 浏览器页签底部那条：控制台 / 网络 / 下载 | `ObserveDrawer.tsx` |
| **净值** | 多次改动后看「**最终改成了什么**」（基线 → 现在），而不是逐次累加 | `shared/line-diff.ts` + `main/net-change.ts` |
| **双口径** | 总账的「N 处 · M 文件」用**原始**计数（含项目外），清单头部用**过滤后**计数 | `FollowPanel.tsx` / `change-list.ts` |
| **页签实例** | 每个页签是一个实例（同一 kind 可多开是**未决**项） | `WorkspaceDock.tsx` |
| **视口联调标记** | 浏览器页签头部的显眼样条，用来定位原生视图与页面区域是否对齐 | `WorkspaceDock.tsx` |

## 六、版本号 `vX.YZ`

`UI-REGIONS.md` §六 里的 `v1.0` ~ `v1.38` 是**界面定义版本号**，**不是应用版本号**（`package.json` 的
`version` 与它无关）。每一条记录「当时」的区域状态与决定——**已被后续版本推翻的会就地标
「⚠️ 已被 vXX 取代」**，读到时不要按它们判断现状。

## 七、内核与外部概念

| 叫法 | 是什么 |
|---|---|
| **harness / lane** | 内核（`@earendil-works/pi-agent-core`）的会话运行时与「会话里的一路运行」。worker 持有一个 harness |
| **compaction（压缩）** | 上下文将满时把历史摘要掉。**算法是内核自带的**，Colt 只负责入口、参数装配、失败翻译与提示 |
| **thinkingLevel（思考等级）** | 会话级配置 `off / low / medium / high`，默认 `high`。⚠️ **默认值不能是 `off`**——pi-ai 的 provider 兼容层会把 `off` 翻译成**显式关闭思考**，对「始终思考」的模型会让**不带工具**的请求直接 400（压缩、审批分析器都因此失效） |
| **toolRpc** | worker → 主进程的宿主能力往返（浏览器 / 电脑控制），由主进程回消息唤醒 |
| **baseline（基线）** | 改动前的内容快照，净值就是「基线 → 现在」 |
| **`kernel_session_id`** | 内核侧的会话标识，与 Colt 自己的会话 id（`externalSessionId`）分开存 |
| **`modelRef`** | `"providerId/modelId"` 形态的模型引用 |
| **审批三模式** | `approval`（白名单放行，其余都问）/ `auto`（白名单外普通操作自动放行，仅 dangerous 仍问，**默认**）/ `full-access`（不拦截） |
| **审批三风险档** | `safe` / `moderate` / `dangerous`。`dangerous` 免疫「不再询问」记忆 |
