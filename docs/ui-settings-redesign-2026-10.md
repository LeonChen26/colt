## 一、一句话

现在的设置页是**一条竖直流水线**：7 个分区首尾相接，每段都是「`<h3>` + 一段解释 + 一张卡片」，作用域全靠用户自己猜。重新设计做四件事——**加导航**、**把设置项从卡片改成行**、**把作用域摆到标题上**、**把说明从常驻改成按需**。

## 二、现状诊断

七条，每条都指到具体位置，不是感觉。

| # | 问题 | 证据 |
|---|---|---|
| 1 | **没有导航，只能滚** | 7 个分区在 `<div className="mx-auto max-w-3xl">` 里顺序挂载：模型服务 → 审批 → 写后诊断 → 上下文压缩 → 可选安装 → MCP 服务 → 技能（`Settings.tsx` L128-134）。「审批」排第 2，但模型服务的每张 provider 卡片含模型行、价格、上下文窗口，很容易超过一屏；MCP 与技能各可能有 N 张卡。找一个开关要先滚过一堆不相关的东西。 |
| 2 | **三种作用域混排，视觉上零区别** | 全局：模型服务 / 审批 / 写后诊断 / 上下文压缩。项目级：MCP 服务（`<rootPath>/.colt/mcp.json`）、技能（`.colt/skills.json`）。用户级：可选安装（写 `~/.colt/mcp.json`，**对全部项目生效**）。三种作用的范围差别极大，界面上一个字的提示都没有。 |
| 3 | **唯一的「保存」按钮是异类** | 写后诊断即时生效（`toggle` 里乐观更新）、压缩失焦提交（`commitTokens`）、技能与 MCP 的开关即时、provider 在卡片内保存——**只有审批**是 textarea + 一颗恒显示的「保存」（`disabled={loading}`，没改动也能点）。同一页五种生效心智，用户无法建立预期。 |
| 4 | **解释文字常驻，占比超过控件** | 技能分区光说明就有三段（`L1041-1056`、`L1064-1071` 等），约 400 字，含两处路径、一个 `/skill` 命令、一段"关掉等于什么"。第一次读有用，第一百次全在挡路。 |
| 5 | **危险度不分层** | 删 provider（密钥一起消失、不可恢复）、卸载 MCP 运行时（删运行目录）、关掉写后诊断——三种后果量级差着数量级，视觉重量一样。 |
| 6 | **看不到「我改过什么」** | 压缩有 `isDefault`、审批有白名单长度、技能有禁用数、MCP 有 server 数——数据都在，界面上一个都没露。用户的真实任务常是「确认」，不是「逐项读」。 |
| 7 | **卡片套卡片** | 每段是 `rounded-lg border bg-surface-raised p-3`，provider 卡片里还有模型行，MCP 卡片里还有 tool 芯片。三层边框叠在同一屏，边界比内容还抢眼。 |

## 三、信息架构

### 分组依据不是「功能模块」，而是「这条设置改变什么」

```
设置
├─ 模型
│  └─ 模型服务     谁能回答我
├─ 行为
│  ├─ 审批         它能不能自己动手
│  ├─ 写后诊断     它写完了检查不检查
│  └─ 上下文压缩   它记不住的时候怎么办
└─ 扩展
   ├─ 可选安装     能装哪些额外工具（用户级）
   ├─ MCP 服务     本项目接入了哪些外部能力（项目级）
   └─ 技能         本项目带了哪些行为约定（项目级，含用户级与内置）
```

**为什么不按作用域分组**（全局 / 项目级 / 用户级）：用户的心智是"我要改模型"，不是"我要改全局设置"。按作用域分组会让「模型服务」和「可选安装」这两个都在设置页顶部的项被拆到两端。作用域用**徽标**表达，不用结构表达。

### 用徽标而不是分组的代价与补偿

徽标的信息量低（10.5px 的灰字），容易被忽略。补偿手段是：用户级那一项（可选安装）额外给**警告色徽标**（"用户级 · 对全部项目生效"），因为它影响面最大且最容易被误以为只影响当前项目。项目级与全局用中性徽标。

## 四、版式与度量

窗口按 1000px 宽实测（`capturePage` + `getBoundingClientRect`）。

| 元素 | 度量 | 说明 |
|---|---|---|
| 左侧导航 | **216px 固定**，`padding: 14px 10px` | 不随窗口缩放；宽度够放最长项「上下文压缩」（5 字）+ 右侧计数 |
| 右内容容器 | `max-width: 672px`，`padding: 22px 24px 40px` | 比现状的 768 窄一点——左栏已经吃掉 216，672 是"一行文字还能顺着读"的上限 |

| 分组标题 | 11px / `letter-spacing: .06em` / 大写 / `--text-muted` | 靠字距与大写做层级，不加线 |
| 分区标题 | 15px / 600 | 现状是 16px（`text-base`），降一档，因为上方已有导航定位 |
| 作用域徽标 | 10.5px / 圆角 4px / `--surface-overlay` 底 | 与标题同行，`gap: 8px` |
| 分区导语 | 11.5px / 行高 1.6 / `max-width: 600px` | 最多两行；超过就砍文案，不放宽 |
| 设置行 | **59px**（两行文字）/ `min-height: 44px`，`padding: 9px 0`，`border-bottom: 1px solid --line-soft` | 行间不用卡片，用 1px 弱线；`--line-soft` 可安全叠在任意表面上 |
| 行标签 | 12.5px / `--text-primary` | |
| 行辅助 | 11px / 行高 1.55 / `--text-muted` / `max-width: 460px` | 一行说完；两行说明这条设置该拆成两条 |
| 开关 | **30 × 17**，圆点 12，行程 13 | 开态轨道 `--accent-dim`、圆点 `--accent-fg`；关态轨道 `--line-strong`、圆点 `--text-muted` |
| 数值输入 | 84px 宽 / 右对齐 / mono 12px | 单位在输入框外，11px 灰 |
| 资源卡 | `padding: 10px 12px`，圆角 8px，**只套一层** | 只有 provider / MCP server / 技能这类"一项资源"用卡片 |

### 开关为什么不用 `--accent`

开态若用近白的 `--accent`（#c9ced6），页面上最亮的东西会变成开关本身，而开关只是"一行设置的当前取值"，不该比正文更抢眼。改用 `--accent-dim`（#7d8694）：与 `--surface` 的对比 **4.3:1**，作为非文本 UI 组件仍高于 WCAG 的 3:1。亮色下开态轨道 `--accent-dim`（#6b7480）配白圆点，对比 5.5:1。

### 亮色下多出来的一条规则

`:root[data-theme="light"] .side { background: var(--surface-raised) }`。暗色下导航与内容同为 `--surface`，靠 1px `--line` 分得开；亮色下内容区是纯白，导航若也用白就与内容融成一片。这是整份稿里唯一一条按主题写的规则。

## 五、组件规格

### 5.1 设置行（`.row`）

设置页的基本单位，替代"卡片 + 卡片内边距"。

```
[ 标签 12.5px                          ]  [ 控件 ]
[ 辅助 11px / muted，最多一行            ]
```

- `align-items: flex-start`，`min-height: 44px`
- 标签侧 `flex: 1; min-width: 0`（长文件名/路径可截断）
- 控件侧 `flex: none`，内部 `gap: 8px`
- `border-bottom: 1px solid var(--line-soft)`，第一行之前再加一条 `--line-soft` 作为组的上边界

**什么时候不用行**：一项资源（provider / MCP server / 技能）有名字、有状态、有附属信息（工具列表、来源、路径），压成一行会丢信息——那类用**资源卡**，但只套一层。

### 5.2 开关（`role="switch"`）

不用原生 `<input type="checkbox">`：现状用的是 `className="h-4 w-4 accent-[var(--accent)]"`，原生复选框在暗色下是系统控件，形状与整站的无彩设计语言不一致，且"关"没有独立语义。

规格：
```html
<button type="button" role="switch" aria-checked="true" aria-label="写后诊断"></button>
```
- 30 × 17 轨道，12px 圆点，`transform: translateX(13px)` 表示开
- `transition: transform 140ms, background 140ms`（用全站同一组缓动）
- `:focus-visible` → `outline: 2px solid var(--accent-dim); outline-offset: 2px`
- **必须带 `aria-label`**：行标签是 `<div>`，不会被读屏联到按钮上

### 5.3 作用域徽标

| 作用域 | 文案 | 样式 |
|---|---|---|
| 全局 | `全局` | `--surface-overlay` 底 + `--line` 边 + `--text-muted` 字 |
| 项目级 | `本项目` | 同上 |
| 用户级 | `用户级 · 对全部项目生效` | `--warning-soft` 底 + warning 边 + `--warning-fg` 字 |

### 5.4 行内折叠（`<details>`）

用于"出问题才要读"的内容：检查明细、`它会跑什么`、手动命令。

- 摘要 11px `--text-muted`，前面一个 4px 三角，展开时 `rotate(90deg)`
- 内容块 `--surface-code` 底 + `--line-soft` 边，11px / 行高 1.65
- 用原生 `<details>` 而不是自制组件：键盘可达、`Ctrl+F` 能在展开后命中、无 JS

### 5.5 危险动作

- 平时只是**灰度图标按钮**（`--text-muted`），hover / `:focus-visible` 才转 `--danger` + `--danger-soft` 底
- 不可逆动作必须二次确认，确认文案写清"什么会跟着消失"（如"删除服务时，它的密钥一起消失，且不可恢复"）
- 不做"红色常驻"：一屏 4 个红图标会让真正的危险失去警示力

### 5.6 审批白名单：从 textarea 改成 token 输入

现状是一个 6 行 textarea，一行一个命令，提交时 `split("\n").map(trim).filter(len>0)`。问题：这是**一个集合**，却用"一篇文本"的控件在编辑——用户会写空行、会写行尾注释、会在中间留空格。

改成 chips：每项一个胶囊 + 末尾一个 inline 输入，回车提交、`×` 删除。语义与数据结构对齐，也不再有"保存"按钮的必要。

> 这一条是**可拆的**：不改也能用（保留 textarea，只把「保存」改成失焦提交）。见 §八 分期。

## 六、逐屏说明

### 6.1 模型服务（全局）

- 顶部保留"密钥只上行不下行"那句，但压到导语里（现状是页面级副标题，只有这一句且与"设置"大标题一起常驻）
- provider 卡只保留：名称 + `OpenAI 兼容` 标签 + 状态（`密钥已配置` / `未配置密钥`）+ 编辑 / 删除图标
- baseURL 用 mono 11px 截断，`title` 给全文
- 模型行压成 chips：`deepseek-v4.1-flash · 128k`
- 底部一句危险预告：「删除服务时，它的密钥一起消失，且不可恢复。若只是换密钥，用编辑。」

### 6.2 审批（全局）

- 行 1：自动审批开关 + 「只对白名单首词生效」
- 白名单：token 输入（§5.6）
- 一句解释下沉到脚注：「匹配的是**首词**，所以 `git push` 与 `git status` 一起放行。想精确到子命令，把整串写进去。」——这是现状完全没有的信息，而它直接决定用户怎么填。

### 6.3 写后诊断（全局）

- 行 1：开关 + 「全仓类型检查在写入停止约 2 秒后于后台运行，不阻塞回复」
- `▸ 它会跑什么` 展开：按扩展名列出 `tsc / eslint / ruff / go vet / cargo check`，并说明「只在项目里存在对应配置时运行；跑不起来就跳过，不会报成错误」

现状把这段信息写成一句长导语（`L256-260`），读完才知道"关掉会怎样"。

### 6.4 上下文压缩（全局）

现状最难读的一段：两个输入框嵌在中文句子中间，横排在 `flex-wrap` 里——

> 压缩后保留最近 `[8000]` 个 token　为摘要预留 `[16384]` 个 token

改成一个阈值一行，标签左、数值右：

| 压缩后保留最近 | `[8000]` token |
| 为摘要预留 | `[16384]` token |

两行各配一句"这行数字意味着什么"。生效值单独一行（10.5px），因为它报的是**服务端钳制后的真实值**（输入 999999 会被钳到上限、输入框回填）——这与"我填了什么"是两件事，不能混。

### 6.5 可选安装（用户级）

沿用 `docs/ui-mcp-catalog-2026-10.md` 的结论（host / payload 两分、检查明细折叠、动作文案四态），另加两条：

- **按状态分小节**：`可安装 · 1` / `已安装`。现状（以及上一稿）所有卡片平铺，装了三项以后已装的会沉到底部，用户找不到"我装了什么"
- 收起态卡片高度从上一稿的 164px 再降（去掉常驻的四行检查），约 **118px**

### 6.6 MCP 服务（本项目）

- 资源卡：名称 + transport + 状态点（`已连接` / `未启动` / `连接失败`）
- 失败态展开一行错误原文（`spawn npx ENOENT —— 命令不在 PATH 上`）+ `重试连接`
- tool 芯片最多显示 4 个，其余折成 `+4`
- 脚注保留现状那条关键区分：「「未启动」不等于「配错了」：会话没打开时只有声明，没有运行态。」

### 6.7 技能（本项目）

- 说明从三段压成一句导语 + 一句脚注
- 项目级技能有警告条（现状有，保留），但改成一行：「本项目用了 2 个项目级技能：它们随仓库分发、会进系统提示词、影响模型行为。」
- 每行：名称 + 来源标签（`项目级` / `用户级` / `内置`）+ 开关 + 定位按钮（内置技能没有定位按钮——磁盘上没有对应文件）
- 脚注保留"关掉 = 不再装载"的完整语义（这句不能砍：它解释了为什么关掉之后 `/skill` 会报错）

## 七、刻意不做的四件事

| 不做 | 理由 |
|---|---|
| **设置搜索** | 只有 7 项。搜索是给 30 项以上的页面用的，7 项加搜索框只会让人怀疑自己漏看了什么。 |
| **「关于 / 版本」分区** | 需要新增只读通道（版本号、数据目录、日志位置）。本稿只动呈现层，不新增 IPC。 |
| **44px 触摸目标** | 这是 Electron 桌面应用，主要输入是鼠标。32px 的导航条目在指针场景更紧凑。若将来上触摸屏，单独加一档 `@media (pointer: coarse)`。 |
| **把「安装流水」提到主进程** | 用户切走设置页再回来，安装进度会丢（组件 state）。修它要改 `mcp.install` 的通道形状，属于接口改动，不在这份稿里。 |

## 八、落地范围与分期

只改渲染层。按"改动风险从低到高"分三期，每期都能单独提交、单独验证。

### P0 · 纯样式（不改结构，~1 天）

| 文件 | 改动 |
|---|---|
| `styles.css` | 无（复用现有令牌，不新增色值） |
| `Settings.tsx` | 每段外层的 `rounded-lg border bg-surface-raised p-3` → 行式；`<h3 className="text-sm">` → `<h2 className="text-[15px]">` + 作用域徽标；顶部 `max-w-3xl` → `max-w-2xl` |
| 全局 | 说明文字从块级 `<p>` 挪到行内 `.hint`（11px）；长段落后移进 `<details>` |

风险：**冒烟断言依赖 `data-*`，不依赖 className**，所以要逐个确认属性还在（见 §九）。

### P1 · 结构（加导航，~2 天）

| 文件 | 改动 |
|---|---|
| `Settings.tsx` | 拆成 `<SettingsNav>` + 7 个 `<SettingsPanel>`；`active` 用 `useState`，默认 `"providers"` |
| 各分区 | 去掉外层的 `mt-6`（间距由 panel 容器统一给） |
| `App.tsx` | 无（设置仍是 `MainView` 的一个整页视图） |

两个必须注意的实现细节：

1. **条件渲染而不是 `hidden`**：只挂当前 panel。否则打开设置页会同时发 7 组 IPC（现状就是这样，一次全拉）。
2. **目录探测要缓存**：`mcp.catalog` 会 spawn 4 条命令（`python --version` × 3 候选 + `git --version`）。条件渲染后每次切到「可选安装」都会重跑，会有明显延迟。用 `useRef` 在设置页会话内缓存一次结果，或给主进程加 5 分钟 memo。

### P2 · 行为统一（去掉「保存」按钮，~1 天）

| 分区 | 现状 | 目标 |
|---|---|---|
| 审批 | textarea + 恒显示「保存」 | token 输入 + 失焦/回车提交，行尾 1.5s「已保存」提示 |
| 其余 | 已是即时 / 失焦 | 不动 |

风险：审批白名单的提交会从"用户主动点"变成"失焦自动"。**必须保证非法内容不会写盘**（现在 `filter(len>0)` 已经在做），且失败要回滚到服务端确认的值——压缩的 `syncDraft` 就是这个模式的现成范例。

## 九、对冒烟的影响

现有两个冒烟模式会碰到设置页：

| 模式 | 依赖 | 影响 |
|---|---|---|
| `mcp-catalog` | `[data-mcp-preset]`、`[data-mcp-probe]`、`[data-mcp-probe-ok]`、`[data-mcp-manual]`、`title="设置"` 的入口按钮 | **会红**。导航化之后打开设置页默认停在「模型服务」，`data-mcp-preset` 不在 DOM 里。改法：给导航按钮加 `data-settings-nav="catalog"`，冒烟先点它再断言。上面四个 `data-*` 全部保留。 |
| `mcp-reload` | 只断言 IPC 形状，`L27` 明确写了"不含设置页 DOM 断言" | 不受影响。 |
| `dock` | 无设置页断言 | 不受影响。 |

**必须原样保留的 `data-*`**：`data-mcp-preset`、`data-mcp-probe`、`data-mcp-probe-ok`、`data-mcp-manual`、`data-mcp-server`、`data-skill-rescan`。

## 十、未覆盖的状态

诚实列出来，评审时不会被问住：

1. **未打开项目时**（`project === null`）：扩展组的两项（MCP 服务 / 技能）应变成 `aria-disabled="true"` 的灰态条目，点击不切换。稿里有这条 CSS 但没有画屏。
2. **安装中 / 安装失败**：沿用 `docs/ui-mcp-catalog-2026-10.md` 已画的状态，本稿没有重画。
3. **首个 provider 都没有的空态**：现状是空白一片 + 「添加」按钮。应该给一句"还没有配置模型服务，助手现在不能对话"。
4. **窗口宽度 < 860px**：左栏 216 会挤占内容区。需要一条断点：< 860px 时导航折成顶部横向 tab。

## 十一、验证方法

这轮做稿踩到一个坑，值得写下来：**不能靠截图判断颜色**。

1060px 窗口 `capturePage` 出来的图，我一度以为审批页的 token 芯片有的是绿色、有的是白色——实际去查 `getComputedStyle` 才发现全部是 `rgb(232, 235, 240)`。细笔画的 mono 字体在暗底上缩放到小尺寸时，subpixel 抗锯齿会造出明显的彩边。

正确做法：

```bash
# 1. 渲染 + 逐屏截图（Electron offscreen，无需 playwright）
./node_modules/electron/dist/electron.exe /tmp/wb-shots/shot-panels.js \
  "E:/code/opensource/colt-wiki-panel/docs/archive/prototype-settings-hifi.html" \
  "$(cygpath -w /tmp/wb-shots)" dark providers,approval,diagnose,compaction,catalog,mcp,skills

# 2. 量尺寸 / 查颜色，一律走 getComputedStyle 与 getBoundingClientRect
./node_modules/electron/dist/electron.exe /tmp/wb-shots/measure2.js <file>

# 3. 结构配对用 Python html.parser 查栈
```

注意 `env -u ELECTRON_RUN_AS_NODE`——本会话全局注入了这个变量，不摘掉的话 Electron 会当 Node 跑，报 `does not provide BrowserWindow`。
