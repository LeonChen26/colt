# Colt 设计原则（宪法）

> **这是什么**：跨版本稳定、**不可违背**的产品与设计约束。它从用户痛点和工业标准（ACP）反推而来，
> 不随某一版界面变动。原先寄生在 v3 设计稿（该稿已删除，界面现状的真源是 `docs/UI-REGIONS.md`）里——
> **最该被遵守的东西不该出现在最该被忽略的设计稿里**，故抽出为独立文件。
>
> **怎么用**：动手前扫一眼。如果你的改动会让某条原则从 ✅ 退回 ⚠️ / ❌，那不是「权衡」，是**退化**。
>
> **元规则（本文件自己的纪律）**：**任何一条原则被实现推翻或部分满足时，必须就地标注状态**，
> 不许留白。这份文件曾经 9 条里 3 条与实现不符却毫无标记——那比没有原则更糟，因为它会持续撒谎。

## 八条原则

> 编号**沿用历史、不重排**——别处按 `#1` / `#8` 这类编号的引用（`DESIGN-subagents.md`、
> `DESIGN-todo.md`）因此继续指得对。**#6 已移出**，见文末「附录：已废弃的原则」。

| # | 原则 | 一句话解释 | 现状 |
|---|---|---|---|
| **1** | **永远有心跳** | 任何等待状态都必须有可见的运动（计时 / 活跃指示），让用户分得清「在思考」与「挂了」 | ✅ 已实现：Live Bar 计时 + 「最后活动 N 秒前」+ 长时间无事件时的「似乎卡住了，可中断」 |
| **2** | **永远可中断** | 任何运行态都能一键停止，且停止后状态回到干净态 | ✅ 已实现：输入区停止按钮；中断同时清空待审队列（不留悬空卡片） |
| **3** | **思考要可见** | agent 的推理过程作为独立信息流展示，而非黑盒 | ✅ 已实现：会话流里的**思考轨**（默认整块折叠，弱化样式） |
| **4** | **上下文实时** | 上下文占用与成本是**持续状态条**，不是事后统计页 | ✅ 已实现：Live Bar 的上下文条（>70% 琥珀 / >90% 红）+ 成本 |
| **5** | **授权对齐标准** | 渲染 agent 给出的选项，四档语义 + 取消；等待有超时；**超时 / 取消不静默** | ⚠️ **部分**：四档决定 + 可见倒计时 + 超时转「已超时自动拒绝」已实现；**「取消」没有界面表现**——用户中断会话时卡片直接消失，不写「已取消」 |
| **7** | **错误讲人话** | 显示真实原因 + **建议动作**，不透传底层原始报错 | ⚠️ **部分**：压缩失败已按此做（`worker/lib/compact-error.ts`），但**只有这一处**——没有「谁负责把哪类内核错误翻成什么文案」的约定。见 `docs/ERRORS.md` |
| **8** | **自动行为不抢焦** | 后台事件不顶掉用户当前视图 | ✅ 已实现：右栏只**追加 / 更新自己那一栏**，绝不改动用户正在看的区域。<br>**边界（v1.39）**：它约束的是「不顶掉用户正在看的视图」，**不禁止请求注意**——「等待授权」是需要用户拍板的状态（5 分钟不处置即自动拒绝），窗口不在前台时必须闪任务栏并发系统通知，否则「没人拍板」与「模型太慢」在界面上一模一样。**仍不抢焦点**：只请求注意，把窗口叫到前台由用户决定 |
| **9** | **用户可省流** | 流式 / 动画 / 轮询都要有开关 | ❌ **未实现**：没有省流开关（设置里也没有） |

## 欠账的处置约定

原则与实现不一致时，**只有两种正当处理**，不允许「放着不管」：

1. **改实现**，让它满足原则（#5 的「取消」、#9 的省流开关都属此类——它们只是没做，不是不该做）。
2. **改原则**，并写明**为什么放弃**。#6 已走完这条路（2026-09-20）：跟随线被证伪，
   原则连同那个视图一起废弃，只留附录供后来者查证——这是本文件第一次真正销账。

> 现状：**#5 与 #9 仍是「欠账」**（它们只是没做，不是不该做），所以在这里是 ⚠️ / ❌，而不是 ✅。

## 与其它文档的分工

本文件只管**产品与设计**层面的原则。其余约束各有宿主，别在这儿重复：

| 主题 | 去哪 |
|---|---|
| 已犯过的错误、动手纪律（文件修改、需求理解、坐标计算…） | `AGENTS.md` |
| 失败如何呈现、错误怎么翻成文案 | `docs/ERRORS.md` |
| 界面各区域的规则与归属 | `docs/UI-REGIONS.md` |
| 跨进程边界与契约变更流程 | `docs/ARCHITECTURE.md` |
| 权限模型与安全边界 | `docs/SECURITY.md` |
| 哪些明确不做、已知缺口 | `docs/NEXT-PHASE.md` §3.2 / §1（下一步计划 §3.1 已清空） |

> **一条从事故里长出来的原则**，因为它同时属于产品与工程、且违反代价极高，所以写在这里：
> **失败必须可见**。任何后台操作失败，用户都必须能看见——静默失败比报错更伤信任。
> 依据：`/compact` 曾因「摘要失败被内核结算成 `ok: true`」而长期无声无息。详见 `docs/ERRORS.md`。

## 附录：已废弃的原则

### #6 文件跟随 ❌（2026-09-20 移出原则表）

**原意**：实时展示 agent 正在读 / 改哪些文件。

**为什么废弃**：它依赖 ACP 的 `ToolCall.locations`，而这个字段在本仓**全仓不存在**、内核也不产出——
原则挂着一份不存在的能力，比没有原则更糟：它会持续撒谎（见文件顶部的元规则）。

**需求没丢，改由另一条路实现**：`fileChanges` + 工具卡 hover → 右栏高亮同一路径。
**不要再按「跟随线」这个视图去设计。** 编号 #6 不再启用，以保持 #7–#9 的引用稳定。
