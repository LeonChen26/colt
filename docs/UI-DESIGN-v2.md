# Banyan · 产品界面设计 v2.0

> **一次彻底的重新构想（重新设计版，抛弃历史包袱）**
> 作者：Banyan
> 技术底座：Electron + React 19 + Tailwind v4 + `pi-agent-core`
> 本文档不继承任何既有布局假设，从"用户到底在用这个东西做什么"重新推导。

---

## 0. 先说结论：v2 与 v1 的根本不同

v1 是"把聊天软件加长加宽"——侧栏 + 消息流 + 输入框 + 若干面板。这是**聊天隐喻**。
v2 抛弃聊天隐喻，改为 **任务执行隐喻**：Banyan 是一张**工作台（Bench）**，用户不是"在聊天"，而是**在派活、在盯工、在验收**。

| 维度 | v1（聊天隐喻） | v2（工作台隐喻） |
|---|---|---|
| 主轴 | 消息流（时间轴） | **任务（Task）**，消息只是任务的日志 |
| 中心 | 输入框 | **当前任务的状态与产出** |
| 组织 | 项目 → 会话 → 消息 | **工作区 → 任务 → 步骤/产出** |
| 面板 | 右侧多选一抽屉 | **左右双翼 + 阶段式工作流** |
| 权限 | 全局模式徽章 | **按操作粒度的即时授权（Inline Grant）** |
| 结束 | 没有明确"完成" | **交付物（Deliverable）与验收** |

> 一句话：v1 回答"AI 说了什么"，v2 回答"活儿干完了吗、干得对不对、我收不收"。

## 1. 重新定义用户与场景

### 1.1 用户的真实心智
用户打开 Banyan 时，脑子里想的是**一件具体要办的事**：
> "把登录超时这个 bug 修了" / "给这个模块补上单测" / "把日志从 winston 换成 pino"

他关心三件事，按顺序：
1. **干完了吗？**（进度）
2. **干得对不对？**（产出可审）
3. **能不能收？**（验收 / 回滚）

**消息流是手段，不是目的。** 所以 v2 的界面主轴是 **Task**，而不是 Message。

### 1.2 五个角色化场景

| 场景 | 用户状态 | 界面应答 |
|---|---|---|
| **派活** | 空手而来，只有一句话 | 一句话输入即开任务，自动命名、自动圈定工作区 |
| **盯工** | 看着 Agent 跑，想了解进展 | 任务大纲（Plan）+ 实时执行日志，进度可量化 |
| **批刀** | Agent 要动危险操作 | 就地授权卡片，粒度到"这一次" |
| **验收** | Agent 说干完了 | **交付页**：改了什么、跑没跑测试、能不能合并 |
| **回溯** | 改坏了 / 想看看历史 | 分支时间线 + 一键回到任意节点 |

## 2. 核心概念重构

```
Workspace（工作区 = 一个本地目录，一等工作公民）
  └── Task（任务 = 一件要办的事，v2 的最小组织单元）
        ├── Intent      一句话目标（用户原话）
        ├── Plan        任务大纲（Agent 拆解出的步骤，可勾选/可编辑）
        ├── Run Log     执行日志（消息 + 工具调用 + 终端输出，合并为一条时间线）
        ├── Artifacts   交付物（文件改动 / 生成的产物 / 命令结果）
        ├── Timeline    分支时间线（可回溯、可分叉）
        └── Verdict     验收结论（待验收 / 已接受 / 已放弃）
```

**关键变化**：
- `Session` 改名 `Task`。不是文字游戏——Task 有**目标、进度、完成态**，Session 没有。
- 新增 `Plan`。Agent 先给大纲，用户先看方向对不对，再放它跑。**这是最有价值的信任建立点。**
- 新增 `Artifacts` + `Verdict`。任务有明确的"验收"终点，而非无限对话。
- `Message` 降级为 Run Log 里的一种条目类型。

## 3. 布局总纲：三区工作台

抛弃"侧栏 + 主区"的聊天骨架，改为**工作台三区**：

```
┌───────────────────────────────────────────────────────────────────────────────┐
│  ① 命令条 Command Bar                                                          │
│  🌳 Banyan   │  工作区：banyan ▾          ⌘K  搜索/命令       ⊕ 新任务     ⚙   │  40px
├───────────────┬───────────────────────────────────────────────┬───────────────┤
│               │                                               │               │
│  ② 任务板       │  ③ 舞台 Stage                                  │  ④ 产出翼      │
│  Task Board   │                                               │  Artifacts    │
│  240px        │  当前任务全屏展开：                              │  320px        │
│               │  ┌─ Intent 条（目标 + 状态 + 耗时）─┐             │               │
│  进行中 ●      │  ├─ Plan 大纲（可勾选）────────────┤             │  改动 diff     │
│  待验收 ◆      │  ├─ Run Log（执行时间线）──────────┤             │  产物列表      │
│  已完成 ✓      │  └─ Verdict 验收栏（底部常驻）──────┘             │  测试/命令     │
│  已归档        │                                               │               │
│               │                                               │               │
│  [+] 新任务    │                                               │               │
└───────────────┴───────────────────────────────────────────────┴───────────────┘
```

**为什么是这个结构**：
- **左翼 = 任务板**：任务取代会话列表。按**状态分组**（进行中/待验收/已完成），而非按时间平铺。用户一眼看到"我有几件活、哪件卡住了"。
- **舞台 = 当前任务**：不是消息流，而是**任务全貌**——目标在顶、计划在中、执行在下、验收在底。四段垂直叙事。
- **右翼 = 产出翼**：交付物常驻右侧，随时对照。不是"点开才有的抽屉"，而是**与任务并列的验收实物**。

三区均可折叠，记忆状态。窄屏（<1100px）时右翼转为浮层，<900px 时任务板抽屉化。

## 4. 逐区详设

### ① 命令条（Command Bar）· 40px

```
🌳 Banyan │ 工作区 banyan ▾ │ ──────────── │  ⌘K 搜索 · 命令 │  ⊕ 新任务 │  ⚙
```

- **工作区切换器**：当前目录名 + 下拉。切换即切换整个任务板上下文。
- **`⌘K` 命令中心**：不是简单搜索，是**一切操作的统一入口**——找任务、找文件、切工作区、切模型、开设置、回滚到节点。**v2 的键盘中枢。**
- **`⊕ 新任务`**：主操作按钮，全局唯一强调色。
- **安全状态**：不再是常驻大徽章（v1 的做法制造了"误点风险"），改为**情境化**——只在任务涉及危险操作时，在任务内就地提示。全局权限收进设置与命令中心。

> v2 决策：**取消全局审批模式徽章。** 原因：全局开关的语义太粗（要么全问要么全不问），用户实际想要的是"这次这个操作要不要问我"。授权应该**就地、按需**发生，见 3.4。

### ② 任务板（Task Board）· 240px

按状态分组的任务卡片列表：

```
进行中  ●  2
┌───────────────────────────┐
│ 修复登录超时 bug           │  ← 标题（用户原话自动生成）
│ ▓▓▓▓▓▓░░░░  3/5 步 · 2 分 │  ← 进度条 + 步骤 + 耗时
└───────────────────────────┘
┌───────────────────────────┐
│ 接入 DeepSeek 流式         │
│ ▓▓░░░░░░░░  运行中…        │
└───────────────────────────┘

待验收  ◆  1
┌───────────────────────────┐
│ 补全 utils 单测            │
│ ✓ 6 文件 · ✓ 测试通过      │  ← 验收摘要
└───────────────────────────┘

已完成  ✓  8
  重构日志模块              昨天
```

**每张卡片承载**：标题 / 进度 / 状态 / 关键里程碑。**卡片本身就是信息**，不需要点进去才知道进展。

- 状态点色：进行中 `success` 呼吸绿 / 待验收 `warning` 琥珀 / 已完成 `muted` / 出错 `danger` 红
- 右键：重命名 / 归档 / 删除 / 复制意图
- 拖拽可跨状态移动（手动标记完成）

### ③ 舞台（Stage）· 当前任务全貌

舞台是 v2 的心脏，四段垂直叙事，从上到下讲一个完整故事：

#### 3.1 Intent 条（目标带）
```
┌─────────────────────────────────────────────────────────────────┐
│ 修复登录超时 bug                          ● 进行中 · 已跑 2:14     │
│ E:\code\opensource\banyan · deepseek-chat · 12.4k tok · $0.0021  │
│                                            [暂停] [插话] [放弃]   │
└─────────────────────────────────────────────────────────────────┘
```
任务的第一身份是**它要办的事**，不是它说的话。醒目展示 Intent，副行放环境与消耗。

#### 3.2 Plan 大纲（可交互计划）
```
计划                                          3/5 完成        [编辑]
✓ 1. 定位超时来源：查看 auth 中间件
✓ 2. 复现问题：读取 session 过期逻辑
✓ 3. 确认根因：token 刷新竞态
▸ 4. 实施修复：加锁重试            ← 当前步骤（高亮）
○ 5. 验证：跑单测                  ← 未开始
```
- **这是 v2 新增的核心信任机制**：Agent 先亮计划，用户可在开跑前**编辑/删除/重排步骤**。
- 已完成的步骤点击可跳到对应日志位置。
- 当前步骤脉冲高亮，用户清楚"它现在在干嘛"。

> 若 Agent 未主动给计划，界面上提供一个"让它先规划"的引导按钮。

#### 3.3 Run Log（执行时间线）
不再是聊天气泡，而是**带类型徽标的执行流**：

```
14:02  💬 你说   修复登录超时，session 20 分钟就掉线
14:02  🤖 Agent  我先定位问题，读一下 auth 中间件。
14:02  🔧 read   src/auth/middleware.ts            0.3s ✓
14:03  🔧 grep   refreshToken                       0.1s ✓
14:03  🤖 Agent  发现 token 刷新存在竞态，多个请求同时刷新。
14:04  🔧 edit   src/auth/token.ts  +12 −4          ✓
14:04  ▶ bash   npm test -- auth                    ← 运行中，实时输出
       │ PASS src/auth/token.test.ts
       │ PASS src/auth/session.test.ts
       └ 2 passed · 1.2s
```

条目类型：
- 💬 用户发言 · 🤖 Agent 文本 · 🔧 工具调用（可展开入参与输出）· ▶ 命令执行（内联终端，实时回写）· ⚠ 授权请求（就地拦截）
- 左侧时间线，右侧内容，**工具条目默认折叠为一行**，点开才看细节，保持流清爽
- 顶部工具条：过滤（只看工具/只看错误）、自动滚动开关、跳到底部

#### 3.4 Inline Grant（就地授权）
**v2 的签名交互**——抛弃全局开关，改为操作就地授权：

```
14:05  ⚠ 需要你的许可
       ┌───────────────────────────────────────────┐
       │ 🔴 危险 · 将覆盖 src/auth/token.ts          │
       │ 原因：检测到文件有未提交改动，覆盖后可能丢失   │
       │ [展开查看 diff]                             │
       │                                           │
       │ [拒绝并说明]      [仅本次允许]  [本任务内允许]│
       └───────────────────────────────────────────┘
```
- **授权粒度三档**：仅本次 / 本任务内同类操作 / 本任务内该工具——把"要不要问"的决策权精确交给用户。
- 风险分色：安全蓝 / 中等琥珀 / 危险红。
- 拒绝时可就地输入原因回传 Agent，引导它换路子。
- **就地性原则**：授权卡出现在它要拦的那一步，而非悬浮在某个全局位置。用户永远知道"我在放行什么"。

#### 3.5 Verdict（验收栏）· 底部常驻
任务完成时，舞台底部升起验收栏：

```
┌─────────────────────────────────────────────────────────────────┐
│ ✅ Agent 认为任务已完成                                          │
│ 改动 3 文件（+28 −12）· 测试 2 passed · 耗时 4:12               │
│ [查看全部改动]  [运行测试]  [拒绝并继续]  [✅ 接受并完成]         │
└─────────────────────────────────────────────────────────────────┘
```
- **"接受并完成"是任务的终点**——归档入"已完成"，产物进入右翼历史。
- "拒绝并继续"让 Agent 接着改，任务保持进行中。
- 未验收的任务一直停在"待验收"分组，形成一张**待办清单**，倒逼收口。

### ④ 产出翼（Artifacts Wing）· 320px

与任务并列的**验收实物**，常驻右侧：

```
产出                           [全部 ▾]
──────────────────────────────────
📝 改动  3 文件                    +28 −12
  ▸ src/auth/token.ts        +12 −4  ⭘
  ▸ src/auth/middleware.ts   +8  −6  ⭘
  ▸ tests/auth.test.ts       +8  −2  ⭘
──────────────────────────────────
▶ 命令 1 条
  ✓ npm test -- auth        2 passed
──────────────────────────────────
📦 生成物
  ▸ .banyan/reports/auth.json
──────────────────────────────────
⏱ 时间线
  ● 当前 · 修复 token 竞态
  ○ 起点 · 初始会话
  [查看分支树 →]
```

四个折叠区：
- **改动**：文件级 diff 摘要，点击展开行内 diff（红绿对比）
- **命令**：任务执行过的命令及结果
- **生成物**：Agent 落盘的报告 / 产物
- **时间线**：分支树入口，可回到任意历史节点

**常驻的意义**：用户在读 Agent 的解释时，能**同时**看到它改了什么，形成"说法 vs 实物"的即时对照。

## 5. 视觉系统

### 5.1 色彩
延续暗色基调，但**降低对比噪点、提升层级**：

| Token | 值 | 用途 |
|---|---|---|
| `surface` | `#0a0c0f` | 应用底 |
| `surface-raised` | `#11141a` | 任务板 / 产出翼 |
| `surface-overlay` | `#161a21` | 卡片 / 悬浮 |
| `border` | `#20262f` | 描边 |
| `text-primary` | `#e8ebf0` | 正文 |
| `text-secondary` | `#98a2b3` | 次级 |
| `text-muted` | `#666f7a` | 占位 |
| `accent` | `#4f9cf9` | 主操作 |
| `success` | `#3fb950` | 完成 / 通过 |
| `warning` | `#d29922` | 待验收 / 告警 |
| `danger` | `#f85149` | 危险 / 失败 |

**状态语义色**贯穿全应用：绿=顺畅、黄=需你决策、红=危险/失败。

### 5.2 排版
- 中英混排 UI 字体；等宽用于路径 / 代码 / 命令 / 时间戳
- 字阶 11 / 12 / 13 / 14 / 16 / 22（任务标题）
- 行高：正文 1.6，代码 1.65

### 5.3 形状与空间
- 圆角：控件 6px，卡片 10px，验收栏 12px
- 4px 基线栅格；卡片内距 14px；区块间距 16px
- **层级靠描边 + 极轻阴影，不靠高对比底色块**

### 5.4 动效
- 状态迁移（进行中→待验收）用 200ms 缓动
- 运行中：进度条微光流动、状态点呼吸
- **克制**：动效只用于状态变化，不做装饰

## 6. 关键交互与快捷键

| 快捷键 | 行为 |
|---|---|
| `⌘K` | 命令中心（找任务/文件、切工作区、切模型、回滚） |
| `⌘N` | 新任务 |
| `⌘⏎` | 发送 / 提交授权决定 |
| `⌘.` | 暂停当前任务 |
| `⌘⇧A` | 打开产出翼 |
| `⌘⇧P` | 展开/收起 Plan |
| `Esc` | 关闭浮层 / 取消当前焦点操作 |
| `J / K` | 在 Run Log 条目间移动 |

**核心理念：键盘走完全流程**——派活（⌘N）→ 看计划（⌘⇧P）→ 授权（⌘⏎）→ 验收（⌘⏎）。

## 7. 状态设计

| 状态 | 界面表现 |
|---|---|
| **空工作区** | 中央一句话输入框 + "描述你想做的事，Banyan 会先给你一份计划" |
| **无进行中任务** | 任务板空态 + 引导新建 |
| **无工作区** | 全屏欢迎页 + 打开目录 |
| **任务启动中** | Intent 条显示"正在规划…"，Plan 区骨架屏 |
| **任务运行中** | 进度条流动、当前步骤高亮、Run Log 自动滚底 |
| **等待授权** | 舞台滚动到授权卡并高亮，任务板卡片显示琥珀点 |
| **待验收** | 底部升起验收栏，任务板移入"待验收"组 |
| **任务出错** | 红色状态点 + 错误条 + "重试 / 换模型 / 放弃" |
| **无密钥** | 中央引导卡 + 直达设置 |

## 9. 从 v1 到 v2 的迁移对照

| v1 元素 | v2 处置 | 理由 |
|---|---|---|
| 会话（消息流为主） | 升级为**任务**（目标+计划+产出+验收） | 聊天隐喻无法回答"干完没" |
| 顶栏全局审批徽章 | 拆为**就地授权卡** | 全局开关粒度太粗、易误触 |
| 右侧多选一抽屉 | 拆为**产出翼**（常驻）+ 计划（移入舞台） | 验收物应与任务并列可见 |
| 设置作为顶级视图 | 降为**命令中心 + 齿轮**入口 | 降低导航噪点 |
| 项目/会话双列表 | 合并为**工作区切换 + 任务板** | 项目是上下文，不是操作对象 |
| 无计划展示 | 新增 **Plan 大纲** | 建立信任的最关键一环 |
| 无完成态 | 新增 **Verdict 验收** | 让任务有终点，形成闭环 |

## 10. 落地优先级

- **P0（骨架）**：三区布局、Intent 条、Run Log 时间线、就地授权、验收栏
- **P1（信任）**：Plan 大纲可编辑、产出翼四区、时间线回溯
- **P2（效率）**：命令中心、快捷键全覆盖、状态分组拖拽
- **P3（进阶）**：多任务并行监控、任务模板、产物导出

---

> **设计内核**：v1 让 Agent"能说话"，v2 让用户"能交办、能验收"。
> 把一次模糊的对话，重塑为一件有目标、有计划、有产出、有结论的**工作**。
