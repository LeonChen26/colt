# 安全边界与权限模型

> **什么时候读这份**：碰审批、文件读写、浏览器 / 电脑控制、密钥之前。
> 这些决策原本分散在 5 个文件的注释里——**安全恰恰是「不能靠读代码来保证一致」的那一类东西**：
> 新增一个工具时，作者不会知道危险命令清单在哪、该不该加。

---

## 零、先说清楚一层：这不是沙箱

`src/main/approval/policy.ts` 的模块说明把它自己讲得很清楚，照抄在此，因为它是最容易被误解的一点：

> 这是一层「**提醒**」而非沙箱：判定基于工具名、参数与命令文本的启发式匹配，刻意偏保守（拿不准就问），
> 但**无法对抗刻意构造的绕过**。真正的隔离要靠操作系统权限或容器，本模块不承担该职责。

所以本文件的定位是：**让「危险的、越界的、含隐私的」动作不被静默执行**，而不是「保证安全」。

**谁不被信任**：

| 不信任的来源 | 为什么 |
|---|---|
| 模型给出的工具入参（路径、命令、URL） | 可能被提示注入或推理错误引导 |
| **渲染层** | 它会渲染 agent 生成的 Markdown——所以绝不能让调用方指定「读哪个根」 |
| agent 访问的网页 | 页面内容会进模型上下文，页面也能构造下载 / 弹窗 / 上传 |

## 一、审批闸门（工具调用的主边界）

### 判定基线：只读白名单

> 只有能证明「无副作用」的调用才自动放行，其余一律进入确认。
> **危险命令清单不参与放行决策**，只用于把风险档位抬到 `dangerous`（更醒目的提示 + 免疫「不再询问」记忆）。

### 三种模式（**会话为单位**，无全局设定）

| 模式 | 行为 |
|---|---|
| `approval` | 只读白名单放行，其余都要确认 |
| **`auto`（默认）** | 白名单放行 + 白名单外的 `moderate` 操作**自动批准**，仅 `dangerous` 仍需确认 |
| `full-access` | 不拦截（等价于旧的全权执行）。切到该模式会**清空本会话已记忆的规则** |

### 三个风险档

| 档位 | 触发 |
|---|---|
| `safe` | 命中只读白名单，且无命令替换 / 重定向等「无法证明无副作用」的特征 |
| `moderate` | 拿不准的一切：非白名单工具、页面操作、**读取整屏截图**（含隐私）、命令含**命令替换或进程替换**（无法可靠拆分）、含**输出重定向**（会写盘）、空命令 |
| `dangerous` | 命中危险命令清单、写项目**外**的文件、改动**敏感文件**、上传敏感文件或项目外文件 |

### 危险命令清单（15 条，`policy.ts` 的 `DANGEROUS_PATTERNS`）

| 命中 | 原因 |
|---|---|
| `rm` / `rmdir` | 删除文件，可能不可恢复 / 删除目录 |
| `mkfs` `fdisk` `diskpart` `format` | 磁盘格式化或分区操作 |
| `dd ... of=` | 直接写入设备或文件 |
| `sudo` / `runas` | 提权执行 |
| `shutdown` `reboot` `halt` `poweroff` | 关机或重启 |
| `curl/wget/iwr/invoke-webrequest` **管道进** `sh/bash/zsh/python/node` | 下载内容直接执行 |
| `git push --force` / `-f` | 强制推送会覆盖远端历史 |
| `git reset --hard` / `git clean -f` | 丢弃未提交的改动 |
| `chmod ... 777` | 放开全部权限 |
| `reg` / `regedit` `add\|delete\|import` | 修改 Windows 注册表 |
| `taskkill` / `kill` / `pkill` 带 `-9` / `/f` | 强制结束进程 |
| `> /dev/sd*` / `> /dev/nvme*` / `> /dev/disk*` | 写入块设备 |
| `npm publish` / `yarn publish` | 发布软件包 |
| `shred` / `srm` | 不可恢复地擦除文件 |

### 敏感文件清单（6 条，即使**在项目内**也升级为确认）

`.env*`（通常含密钥）、`.git/`（直接改动 git 内部）、`.ssh/`、`id_rsa|id_ed25519|id_ecdsa|id_dsa`、
`*.pem|*.key|*.pfx|*.p12|*.jks`、依赖锁文件（`package-lock.json` / `pnpm-lock.yaml` / `yarn.lock`）。

写入 / 编辑与**浏览器上传**共用这份清单：**项目外或敏感文件一律 `dangerous`，每次单独确认**。

### 记忆规则（降噪机制）

- 两种粒度：`tool`（该工具全部放行）/ `signature`（仅放行**同签名**的调用）。
- **`dangerous` 免疫记忆**——危险调用**必须每次单独确认**，不接受「不再询问」。
- 另有**拒绝规则**：命中即自动拒绝，不再打扰用户。
- **寿命与存放**：记忆规则与审批模式**只存在于内存、以 Colt 会话为单位存活**——不落盘，删会话或退出应用即失效。
  设计取舍很明确：**权限决定不应悄悄长期生效**。代价是重启后需重新授权。
- 待审队列**与 worker 同寿命**（worker 没了，阻塞在 `before_tool` 的调用方也没了）。

### 超时与失败方向

- 审批等待上限 **5 分钟**（`store.ts` 的 `DEFAULT_TIMEOUT_MS`），超时按**自动拒绝**处理，界面上会显示「已超时自动拒绝」。
- 自动审批模式下的**大模型分析器**（`approval/analyzer.ts`）是 **fail-closed**：分析不出来就回落到人工确认，且有独立超时。
  它只被允许自动放行**结构上落在首词白名单内的 `moderate` 操作**（`approval/config.ts` 可配），其余一律人工。

### 技能（Agent Skills）：**不进审批闸门**的一条隐式信任通道

`src/worker/lib/skills.ts` 在会话启动时扫两个目录，把发现的技能交给内核写进**系统提示词**：

| 目录 | 层级 |
|---|---|
| `<项目>/.agents/skills` | 项目级（同名时**它胜出**） |
| `~/.agents/skills` | 用户级 |

- **为什么不经审批**：技能是**声明式文本**（`SKILL.md` 正文），不是工具调用——装载发生在会话开始前，
  没有一次「工具调用」可供闸门拦截，且装载本身**只读盘、不改盘**。
- **为什么要如实告知**：正文**会进系统提示词**，等于让磁盘上的文件影响模型行为。所以装载数、层级构成、
  同名覆盖、解析告警**全部走 `notice` 报给用户**（`describeSkills`）。理由一句话：
  **「工具去改文件」要审批，「文件内容改模型行为」却悄无声息，是同一条边界上的两个口子。**
- **目录唯一**：只在上面这两个标准路径（agentskills.io 约定）里找，**没有「从任意路径加载」的入口**——
  少了这条入口，就没有「调用方指定读哪个根」的问题（对照 §三 的根不可由调用方指定）。
- ⚠️ **`~/.agents/skills` 能读到，是因为 `NodeExecutionEnv.resolvePath` 没有工作区边界**（绝对路径原样解析、
  支持 `~/`）。也就是说**这两个目录的写权限与工作区同价**——`~/.agents/skills` 属于用户自己，
  不要为了别的功能去放宽这个边界。

### 记忆系统（AGENTS.md + 双级记忆 + 检索索引）：三条面

**写入面（进审批）**：记忆文件（项目级 `.colt/memory.md`、用户级 `~/.colt/memory.md`）与
AGENTS.md 都由助手经 write/edit 修改——项目内走常规审批；用户级在项目之外，按 §一 属
dangerous、每次单独确认。**没有绕过 write/edit 的记忆写入入口**（检索索引只读文件，不收写请求）。

**注入面（隐式信任通道，如实告知）**：AGENTS.md（父链）、双级记忆每请求注入系统提示词——
装载几份、读失败、文件集合变化、截断都走 `notice`（同技能节的理由：文件内容改模型行为不能悄无声息）。

**检索面（L3a，`main/db/memory-index.ts`）**：`memory_search` 让模型按需检索历史记忆，带来
**记忆的跨会话持久化**——这是一条比技能更强的信任通道，边界如下：

| 面 | 规则 |
|---|---|
| 真源 | 记忆文件是唯一真源；`data/memory.db` 是**派生索引**，可随时删除重建 |
| 项目隔离 | **在 main 侧强制**（`memory-host.ts`）：cwd 由主进程按 `sessionId → 项目 → root_path` 反查推出（`sessions` 表不存 cwd），检索只放行本项目 + 用户级条目，**其它项目的历史记忆一律不可见** |
| 持久注入风险 | 一条被污染的记忆会在未来所有会话复活。缓解：写入面过审批；检索结果带 scope/「现行/已归档」/日期标注（模型可判断新旧）；条目落库带来源会话 |
| 冷层 | 「从记忆文件删掉」≠「记忆消失」：被移除的条目转入 archived、仍可检索。**彻底清除 = 删除 `data/memory.db`**（与核心库同目录，核心数据不受影响） |
| 审批 | `memory_search` 只读、本地、无副作用 → 在 §二 白名单里，不进审批队列 |

**整理面（L3b，`/memory-tidy` → worker 子 lane）**：显式命令触发一轮「合并重复、删过时」，
需要时整体重写 `.colt/memory.md`。安全性质由既有设施兜住，**没有新开口子**：
整理跑在独立子 lane（`harness.lane("memory-tidy")`），工具白名单硬性限为 `read / write / memory_search`；
写文件**照常走审批闸门**（HookRegistry 全 harness 共享，子 lane 不豁免）；**费用照常计入会话统计**
（telemetry 的用量上报**不分 lane**——整理与子代理的调用都是真实发生的计费请求，藏起来是静默，
见 `docs/ERRORS.md`；**上下文占用条仍只算主 lane**，子 lane 的占用不该顶满主上下文条），
但对记忆文件的改写**如实进会话的文件改动记录**（`after_tool` 的记录器不分 lane——诚实报告，不藏）。
主 lane 忙时拒绝（避免与运行中任务的沉淀写入并发改
同一个文件）；整理完成经 `notice` 报结果，被清理的条目就地归档进冷层。v1 不碰用户级记忆。

**子代理面（`subagent` 工具 → 同会话子 lane）**：与整理面同一条 lane 机制，但由**模型自主委派**触发。
安全性质由既有设施兜住，**没有新开口子**：

- **`subagent` 自身免审批闸门**（`docs/DESIGN-subagents.md` 决策四 D6）——否则同一件事弹两次卡
  （委派一次 + 子代理内部工具各一次），用户会去关审批，那更糟。**安全性不降**：委派的副作用
  **全部落在子代理的工具调用上**，那里照常过 `before_tool`——读是免审批的（只读白名单），
  写 / 执行会弹卡 ⇒ 「免审批地委派一个只读调研」是安全的，而「委派一个删目录的动作」会在
  子代理那层被拦下，**没有绕过路径**。（豁免在 `before_tool` 与 `after_tool` 两处都显式写，
  与 `ask_user` 同一处理方式。）
- **工具面是硬白名单**：定义文件里那行 `tools` 决定子代理能碰什么，按 lane 持久化；
  名字不存在**不静默丢**（静默丢会让子代理「看着能读、其实没有工具」）。
- **禁止递归**（depth = 1）：白名单不含 `subagent`，外加 worker 守卫「调用方不是主 lane 就拒绝」——
  自我复制 + 费用失控是最容易失控的一类。
- **定义是一个隐式信任通道**（`.agents/agents/*.md` 来自磁盘，会决定系统提示词与工具面）：
  装载了什么、被谁遮蔽、哪个文件坏了都**如实报出**（`describeAgents`），与技能同一口径。
- **计量**：费用计入会话统计（带归属，`ViewSubagent.stats`）、上下文占用只算主 lane（同上）。
- **可见且可中止**：④ 活卡 +「任务摘要」此刻段一行 + 可下钻看完整过程；**可从界面中止单个子代理**
  （不动主对话、不动别的子代理）。子 lane 对主对话的 `watch` **天生不可见**，所以这些显式出口不是
  装饰，是「它正在花钱」这件事的唯一可观测面。

## 二、只读工具白名单：唯一真源

`src/shared/readonly-tools.ts` 是**唯一真源**，跨进程两处消费，语义必须完全一致：

| 消费方 | 用途 |
|---|---|
| `main/approval/policy.ts` | 名单内的工具**不对用户工作区产生副作用** → 直接放行、不进审批队列 |
| `worker/entry.ts` | `after_tool` 的「未经闸门即执行」安全告警据此豁免——既然 policy 保证放行，本就不该经过闸门 |

当前名单：`read, grep, glob, ls, list, search, todo, memory_search`。

⚠️ **两份列表一旦漂移，要么对合法调用刷告警、要么遮蔽真正的漏报。** 新增只读工具**必须**加进这里，
不要在别处另写一份。

**口径是「不对用户工作区产生副作用」，不是「不产生任何副作用」**——判据看的是**用户的文件**，
不是我们自己的 SQLite。`todo` 就是这条口径的样本：它**会写库**（会话的待办清单落 `todos` 表），
但它仍可免审批，理由逐条如下：

| # | 边界 | 为什么模型越不过去 |
|---|---|---|
| 1 | **入参里没有任何路径** | `subject` / `activeForm` / `status` / `blockedBy` / `ids` 都是标识与文本，**没有 path 字段**——没有可越界的对象 |
| 2 | **写入目标是应用自有的库** | 落点是 `todos` 表（在 `%APPDATA%` 下的 `colt.db`），不是用户工作区的任何文件 |
| 3 | **会话隔离由主进程强制** | 会话 id 取自 `entry.sessionId`（主进程侧），**不采信 worker 传来的 sessionId**——模型无法把清单写到别的会话去过 |
| 4 | **写入不产生文件系统副作用** | 整个 `TodoStore` 只经 DAO 碰库，没有任何 fs 调用 |

所以它和 `read` / `grep` 这类只读工具同属「不对用户工作区产生副作用」这一档。**它之所以不同寻常，
是因为它是「会写库却仍免审批」的第一例**——口径因此从「不产生副作用」收紧为「不对**用户工作区**产生
副作用」。新增沿此例的工具时，必须逐条走上面这张表，而不是因为它「看起来像内部账本」就并进白名单。

## 三、文件读取（预览）：三重校验 + 根不可由调用方指定

`src/main/file-read.ts` 存在的**全部理由**是安全边界：入参来自渲染层，而渲染层会渲染 agent 生成的
Markdown——**所以绝不能让调用方指定「读哪个根」**。根由 IPC 层从**会话所属项目**查出后传入。

| # | 校验 | 挡什么 |
|---|---|---|
| 1 | `resolve` 后必须在根内 | `../` 逃逸；根外的绝对路径 |
| 2 | `realpath` **之后再判一次** | 根内的软链接指向根外 |
| 3 | 大小上限 + 二进制判定 | 别把几十 MB 二进制塞进 IPC 与渲染层 |

**为什么收绝对路径**（易被误判为不安全）：工具入参里的 path 由模型给出，**可能就是绝对路径**；若只收相对
路径，「点 read 出来的绝对路径」就永远打不开。收绝对路径**不削弱安全**——包含性判断是**纯字符串运算**，
**先于任何 fs 访问**：根外的绝对路径在 `isWithin` 就返回，**不会碰磁盘**，因此没有存在性探测的先手。

上限：文本 **1MB** / 图片 **8MB**，超出**直接报「过大」而不截断**——半截文件比看不到更容易误导。

## 四、浏览器边界

- **独立 partition**，与产品界面隔离。
- **只放行 http / https**。
- **新窗口请求被拦截**并在当前窗口打开（不让 agent 或页面把用户甩到看不见的窗口）。
- **下载有界**：每会话 **5 个**、单文件上限 **100MB**，落盘路径受控。
- **观测缓冲上限 300 条**；`CaptureBuffer` 只在**接管新窗口**时重置。
- 页面上传与页面操作都要过审批（见上：上传敏感 / 项目外文件 → `dangerous`）。

---

## 五、电脑控制（Computer Use）

读整屏截图 + 注入键鼠（`desktopCapturer` + PowerShell / user32）。这是**权限最高**的能力：

- 截图定为 `moderate`（无副作用但**含隐私**，可被会话记忆降噪）。
- 键鼠注入必然改变系统状态，**不接受自动放行**。
- 截图有 **2 分钟 TTL**，不无限留存。

---

## 六、密钥与隐私

- 密钥用 Electron **`safeStorage` 加密后落盘**；**明文只存在于内存与 worker 进程的环境变量**里。
- 界面里**密钥只上行、不下行**——设置页看得到「是否已设置」，看不到明文。
- 不需要鉴权的本地服务（`requiresKey === false`）启动 worker 时会填一个**占位假密钥**——因为 pi-ai 的
  `openai-completions` 层无法表达「这个服务不需要鉴权」，`apiKey` 为空会直接抛错。
- **没有账号、没有服务端、不上传会话数据**。会话与用量记录存在本机 SQLite。

---

## 七、数据

- 本机 SQLite（`node:sqlite`），schema 用 `PRAGMA user_version` 管版本，当前 **9**。
- 迁移**必须带存量数据断言**（`tests/migration.test.ts`），并且要明确「旧数据留 `NULL`」是否是一种语义。
  例：`thinking_level` 的 `NULL` = **从未选过**，与「显式选过 `off`」是两回事——迁移把它写成 `off`
  会真的改变行为（而 `off` 会让「始终思考」的模型拒绝无工具请求，见 `docs/GLOSSARY.md` §七）。
- 迁移在事务里按版本升序执行，成功后写 `user_version`。

## 八、改这些边界时要动哪些文件

| 你想改 | 要动 |
|---|---|
| 危险命令 / 敏感文件的判定 | `main/approval/policy.ts`（纯函数，**记得补单测**：`tests/approval.test.ts`） |
| 只读工具名单 | `shared/readonly-tools.ts`（**唯一真源**，两处消费） |
| 审批模式、记忆规则、超时 | `main/approval/store.ts` + `shared/protocol.ts` 的 DTO |
| 分析器可自动放行的命令白名单 | `main/approval/config.ts`（存 `settings` 表） |
| 文件预览的根 / 上限 | `main/file-read.ts` + 调用它的 IPC 落点 |

| 技能装载的目录与告知口径 | `worker/lib/skills.ts`（目录纯函数 + 文案，**记得补单测**：`tests/skills.test.ts`） |

## 九、已知缺口

1. **「取消」没有界面表现**（原则 #5 部分未满足）：用户中断会话时待审卡片**直接消失**，不显示「已取消」——
   主进程侧的清理是完整的（`clearPending`），缺的只是告知。
2. **`full-access` 是真正的旁路**：它按设计不拦截，只适合完全可信的本地实验场景。
3. **没有省流开关**（原则 #9）：轮询 / 流式 / 动画都关不掉。
4. **审批记忆不落盘**是刻意取舍，不是缺陷——但用户会反复授权同一件事，长期看可能需要「项目级」而非
   「会话级」的规则（尚未设计）。
