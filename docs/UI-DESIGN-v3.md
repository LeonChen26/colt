## 0. 一句话立意

> **v1 让 Agent「能说话」，v2 让用户「能交办」，v3 让用户「放心」。**

调研显示用户最痛的两件事：
- **不知道它在干嘛** → 需要**可观测性**
- **卡住停不下来 / 状态不同步** → 需要**可控性**

v3 的全部设计围绕**这一对核心体验**展开。功能可以少，但这两点要做到极致。

## 1. 设计宪法（基于证据）

从调研中提炼的不可违背的规则：

| # | 规则 | 证据来源 |
|---|---|---|
| **1** | **永远有心跳**：任何等待状态都必须有可见的运动（计时 / 活跃指示），让用户能区分"在思考"与"挂了" | 痛点 A：多处"卡住不回复""一直 loading" |
| **2** | **永远可中断**：任何运行态都能一键停止，且停止后状态必须回到干净态 | 痛点 A/D |
| **3** | **思考要可见**：Agent 的推理过程作为独立信息流展示，而非黑盒 | ACP `agent_thought_chunk` |
| **4** | **上下文实时**：上下文占用与成本是持续状态条，不是事后统计页 | ACP `usage_update`（used/size/cost） |
| **5** | **授权对齐标准**：渲染 Agent 给出的选项，支持四档语义 + 取消；等待有超时；超时/取消不静默 | ACP Permission（allow_once/always, reject_once/always, Cancelled） |
| **6** | **文件跟随**：实时展示 Agent 正在读/改哪些文件 | ACP `ToolCall.locations` → follow-along |
| **7** | **错误讲人话**：显示真实原因 + 建议动作，不透传底层原始报错 | 痛点 B：#1239 错误误导 |
| **8** | **自动行为不抢焦**：后台事件不顶掉用户当前视图 | 痛点 E：文件树被 D 盘顶掉 |
| **9** | **用户可省流**：流式 / 动画 / 轮询有开关 | 痛点 F：免费额度用户想关流式 |

## 2. 核心模型：会话现场（Live Session）

ACP 的 11 种 `SessionUpdate` 就是界面必须承载的全部实时状态。v3 把它们**归并为四层**，形成"会话现场"：

```
Live Session（会话现场 = 一个正在发生的工作场景）
│
├── ① 现场状态栏 Live Bar        ← usage_update / current_mode_update
│      模型 · 上下文占用条 · 成本 · 模式 · 心跳计时 · [中断]
│
├── ② 思考轨 Thought Rail         ← agent_thought_chunk  ⭐调研新增
│      Agent 的推理流，可折叠，默认半透明弱化
│
├── ③ 行动流 Action Stream        ← tool_call / tool_call_update / message_chunk
│      消息文本 + 工具卡片（内嵌 Diff）+ 授权卡 + 命令执行
│
└── ④ 跟随线 Follow Line          ← tool_call.locations  ⭐调研新增
       横贯右侧的"Agent 正在碰的文件"实时列表
```

**为什么这样分层**：调研痛点全落在"看不见 / 控不住"。四层分别回答：
1. **现场状态栏**：现在什么情况？（治痛点 A、C）
2. **思考轨**：它在想什么？（治痛点 A）
3. **行动流**：它在做什么？（主体）
4. **跟随线**：它碰了哪些文件？（治"不知道改了啥"）

> ⚠️ **④ 已废弃**（见文首状态表）：实现里没有 `ToolCall.locations`；它成了 ⑦ 右栏的默认页签「正在处理」。

## 4. 逐区设计

### ① 现场状态栏（Live Bar）· 治痛点 A/C/上下文

```
deepseek-chat ▾ │ ▓▓▓▓░░░░░░ 38% (12.3k/32k) │ $0.0021 │ 审批模式 ▾
                                              ⏱ 运行中 02:14 · 最后活动 3s 前  [暂停] [中断]
```

**这是 v3 最重要的新组件。** 它把 ACP 的 `usage_update` + 状态心跳压进一条**常驻在会话顶部**的窄条。

> ⚠️ **实现差异**（见文首状态表）：位置在**输入区下方**（不是会话顶部）；而且是**只读区**——模型 / 模式选择与中断都不在这里（归 ⑤ 输入区），「压缩上下文」入口归 ② 会话头。

- **上下文气泡**：`used/size` 实时进度条。>70% 琥珀，>90% 红，并**提前**浮出"压缩上下文"按钮（治痛点 B：事前预警，而非事后报错）。
- **成本**：累计 `cost` 实时显示。
- **心跳**：`运行中 02:14`（已运行时长）+ `最后活动 3s 前`（距上次事件）。**这是治"卡住焦虑"的核心**——数字在跳，用户就知道它还活着；数字停太久，用户就知道可以中断了。
- **中断**：常驻红字按钮，一键停止。停止后 Live Bar 立刻变灰"已中断"，不残留转圈（治痛点 A/D）。
- **模式**：`审批模式 ▾` —— 注意，这是**会话级**模式（对齐 ACP `SessionModeState`），不是全局开关（修正 v1）。

> 微交互：运行中 Live Bar 左缘有一条**呼吸边的微光**缓慢流动；心跳数字每秒 +1。全程 ≤200ms 的轻量动画，不喧宾夺主。

### ② 思考轨（Thought Rail）· 治"不知道在干嘛"

```
┌────────────────────────────────────────────────┐
│ 💭 思考中…                                   ▾  │
│ 我先确认 token 刷新逻辑是否有竞态：如果多个请求  │
│ 同时检测到过期，会同时发起刷新，后发的覆盖先发的…│
└────────────────────────────────────────────────┘
```

- 对应 ACP `agent_thought_chunk`：**推理过程单独成流**，与正式回复（Action Stream 的 agent_message）分开。
- **视觉弱化**：斜体、`text-muted` 色、半透明底，**不抢主回复的注意力**——它是"氛围组"，让用户安心，而非必须阅读。
- **可折叠**：默认只显示最近几段，可展开看全过程，也可整体关闭（对齐宪法 #9 省流）。
- 流式追加，带轻微淡入。

> ⚠️ **实现差异**：默认是**整块折叠**（不是「显示最近几段」）；「整体关闭」的省流开关未做。

> 设计理由：调研痛点 A 的本质是"看不见过程"。把思考显性化，是**最低成本的安心感**——用户看到它在"动脑子"，就不焦虑了。

### ③ 行动流（Action Stream）

对话与工具**合并为一条时间线**，但工具默认折叠成一行：

```
你    修复登录超时，session 20 分钟就掉线
Agent 根因是 token 刷新存在竞态，我来加锁重试。
🔧 edit  src/auth/token.ts                    +12 −4   ✓ 0.4s   [展开]
🔧 grep  refreshToken                         0.1s   ✓   [展开]
▶ bash  npm test -- auth                                 ● 运行中
        │ PASS src/auth/token.test.ts
        │ PASS src/auth/session.test.ts
        └ 2 passed · 1.2s
```

- **工具卡片内嵌 Diff**：对齐 ACP `ToolCallContent.Diff`——编辑类工具展开后**直接显示红绿 diff**，无需跳转。
- **工具类型图标**：对齐 ACP `ToolKind`（read/edit/delete/move/…），图标语义化而非都用扳手。
- **命令执行内联终端**：`▶ bash` 实时回写输出。
- **过滤**：顶部可切"全部 / 仅工具 / 仅错误"。
- **跟随联动**：hover 某个工具卡片，右侧跟随线高亮它碰的文件。

> ⚠️ **未实现**：「全部 / 仅工具 / 仅错误」这组过滤不存在。（末条的「跟随联动」已实现：工具卡 hover → 右栏高亮同一路径。）

### ④ 跟随线（Follow Line）· 治"不知道改了啥"

> ⚠️ **已废弃**（见文首状态表）：本节整体不成立，对应能力由 ⑦ 的「正在处理」承担。

```
Agent 正在处理
────────────────
✎ src/auth/token.ts       +12 −4   ● 刚刚
👁 src/auth/middleware.ts          ● 2s 前
✎ tests/auth.test.ts      +8 −2    ● 12s 前
────────────────
本次改动 3 文件  +28 −12   [查看全部]
────────────────
会话时间线
  ● 当前
  ○ 起点
  [分支树 →]
```

- 忠实实现 ACP `ToolCall.locations` 的 **"follow-along"**：实时列出 Agent 正在读（👁）/ 改（✎）的文件。
- 每项带**时间戳**"几秒前"，与 Live Bar 心跳呼应——**活动在动，证明它还活着**。
- 底部：本次改动汇总 + 分支树入口。
- **不抢焦**（宪法 #8）：它只**追加/更新**自己的列表，绝不改动用户正在看的其他区域。

### ⑤ 授权卡（对齐 ACP 权限模型）

**这是从 ACP 标准直接得来、修正 v1/v2 的关键组件**：

```
┌──────────────────────────────────────────────────────────┐
│ ⚠ 需要你的许可                                  ⏱ 45s 后超时 │
│                                                          │
│ 操作：覆盖写入 src/auth/token.ts                          │
│ 原因：检测到该文件有未提交改动，覆盖可能丢失                  │
│ [展开查看 diff]                                           │
│                                                          │
│ [ 允许一次 ] [ 本会话内始终允许 ] │ [ 拒绝一次 ] [ 始终拒绝 ] │
└──────────────────────────────────────────────────────────┘
```

- **选项由 Agent 提供**（对齐 ACP `RequestPermissionRequest.options`）——界面**渲染收到的选项**，支持 ACP 的四档 `kind`：`allow_once` / `allow_always` / `reject_once` / `reject_always`。
- **可见超时**：卡上直接显示倒计时（Colt 后端已有 `APPROVAL_TIMEOUT_MS`，**必须暴露到界面**）。超时后卡片转为"已自动拒绝"，不留悬念（治痛点 D）。
- **取消语义**：用户中断会话时，所有待决授权立即变为"已取消"（对齐 ACP `Cancelled` outcome）。
- **风险分色**：安全 / 中等 / 危险。

> ✅ **已实现**。两处偏差见文首状态表：`dangerous` 时刻意不给「本会话内始终允许」；用户中断时卡片直接消失，界面不显示「已取消」。

### ⑥ 输入区

```
┌──────────────────────────────────────────────────────┐
│ 输入消息，Enter 发送 · Shift+Enter 换行                │
└──────────────────────────────────────────────────────┘           [发送]
运行中时占位提示 → "输入将作为插话…" ；队列积压时提示"队列 2 条"
```

- 运行中发送 = 插话（steer）。
- 命令菜单：对齐 ACP `available_commands_update`，输入 `/` 弹出**Agent 动态下发的可用命令**。

> ⚠️ **明确不做**：本仓没有命令注册表，只本地识别**两条**命令——`/compact`（零参数，必须**独占整条输入**）
> 与 `/skill <名字>`（**必须给名字**；命令字整段相等即可，后面还能跟额外指示）。判据都从紧，
> 以免把 `/compact 一下` 这类正常提问静默吞掉。

### ⑦ 会话侧栏

按状态分组（进行中 / 待验收 / 已完成），每项带状态点与心跳：运行中的会话显示**呼吸绿点**，方便切走再切回时一眼找回来（治痛点 C：状态不同步）。

> ⚠️ **状态分组未实现**：左栏是「项目 → 会话 → 分支树」；会话行的**呼吸绿点与计时已实现**。

### ⑧ 设置

分区块：Provider 与密钥 / 会话模式默认值 / 授权策略（始终允许的签名与工具白名单）/ 环境信息 / 数据与隐私 / **省流开关**（关闭流式、关闭动画——治痛点 F）。

> ⚠️ **大部分未实现**：设置里只有「模型服务」与「审批白名单」；授权规则的查看 / 删除在**会话级**的「规则」页签里。

## 5. 视觉系统（相对 v2 微调）

- **配色核心不变**（暗色开发者基调），新增语义：
  - 思考轨：`text-muted` + 微透明底（弱化）
  - 跟随线"刚刚"高亮：`accent` 淡色
  - 心跳存活指示：`success` 微光
- **诚实的状态色**：绿=顺畅运行、黄=等你决策、红=危险/失败、灰=静止/已结束。**颜色必须配文字**，不单靠颜色（无障碍）。
- **动效克制**：只服务"证明它还活着"（心跳、进度微光、流式光标）。≤200ms，且可全局关闭。
- **字体**：中文 UI 常规，路径/代码/工具名/计时用等宽。

## 6. 关键状态与异常（本设计的重点，因调研）

| 状态 | 表现 | 治什么 |
|---|---|---|
| **在思考**（等模型） | 思考轨出现"💭 思考中…" + Live Bar 心跳 | 痛点 A |
| **在执行工具** | 工具卡转圈 + 计时 + 跟随线高亮该文件 | 痛点 A |
| **等待授权** | 授权卡 + 倒计时 | 痛点 D |
| **长时间无事件** | 心跳"最后活动"数字变大；超阈值时 Live Bar 转琥珀并提示"似乎卡住了，可中断" | 痛点 A ⭐ |
| **上下文将满** | 上下文条 >70% 琥珀，浮出"压缩" | 痛点 B |
| **上下文已满** | 明确"上下文超限，建议压缩/开新会话"，**不伪装成模型错误** | 痛点 B |
| **任务异常结束** | Live Bar 变灰"已中断/已结束"，清除所有转圈 | 痛点 A |
| **后台事件到达** | **不改变**用户当前视图，仅在对应区域静默更新 | 痛点 E |

> **"长时间无事件"是本报告催生的全新状态**——痛点 A 的正面解法：不制造假活动，而是**如实显示"多久没动了"并主动提示可中断**。

## 9. 与 ACP 标准的能力对照表

本设计明确覆盖 ACP 的实时模型（也是面向未来的兼容准备）：

> 逐项实现状态见**文首状态表**：`plan` 与 `available_commands_update` 未实现（后者已决定不做），`ToolCall.locations` 已废弃，`current_mode_update` 的位置已改到 ⑤。

| ACP 能力 | v3 落点 |
|---|---|
| `agent_thought_chunk` | 思考轨 ② |
| `agent_message_chunk` / `user_message_chunk` | 行动流 ③ |
| `tool_call` / `tool_call_update` | 工具卡片 ③ |
| `ToolCall.content.Diff` | 工具卡内嵌 diff |
| `ToolCall.locations` | 跟随线 ④ |
| `plan` | 会话内计划条（并入行动流顶部，简化） |
| `usage_update` | 现场状态栏 ① |
| `current_mode_update` / `SessionModeState` | Live Bar 模式选择（会话级） |
| `available_commands_update` | 输入区 `/` 命令菜单 |
| `RequestPermission.*` + 四档 kind + Cancelled | 授权卡 ⑤ |

> **战略价值**：v3 的界面模型与 ACP 对齐，意味着未来若接入 ACP 生态（编辑器 / 远程 / 多 agent），界面**几乎零改动**。
