先确认 token 刷新是否存在竞态，再决定加锁方案。

定位到根因了——不是超时时间太短，而是刷新 token 存在竞态。多个并发请求同时检测到过期时，会各自发起刷新，后到的响应覆盖先到的，导致部分请求拿到已失效的 token。

修复思路：给同一 userId 的刷新加锁，只允许一个在飞行中。改动如下：

typescript 复制
async function getToken(userId: string) {
  return withLock(userId, async () => {
    const cached = cache.get(userId);
    // 命中未过期的缓存则直接返回
    if (cached && !isExpired(cached)) return cached;
    log('refreshing token', userId, 3000);
    return refresh(userId);
  });
}

同时需要处理两点：

  • withLock 要支持超时释放，避免死锁
  • 刷新失败时清除本地缓存，防止拿到旧值

你之前遇到的报错：

Error: token expired at request #42

验证方式：跑 npm test -- auth，已补一个并发刷新的用例。
