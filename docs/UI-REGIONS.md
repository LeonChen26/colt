# Colt 界面区域定义（现状真源）

> **作用**：约束后续 UI 修改——任何新增 / 移动功能，先在此找到归属区域，再动手。
> **定位**：开发者自用的桌面 Agent 工作台，Work 模式。
> **边界**：只定义**结构职责**，不定义视觉细节。
> **读法**：判断现状**只看 §一~§五**；§六 是版本表，只作追溯。落地细节（文件名 / 阈值 / 锚点）随规则写在文中。
> 相邻文档：跨进程契约 → `ARCHITECTURE.md`；安全边界 → `SECURITY.md`；失败如何呈现 → `ERRORS.md`；计划 → `NEXT-PHASE.md`。

---

## 零、总原则

1. **一个区域只回答一类疑问。** 功能回答的疑问与所在区域不符时，应当搬家，不是就地妥协。
2. **区域按「视角」分层。** 全局 / 会话级 / 运行态 / 外部世界——不同视角的信息不混放。
3. **只读区不承载操作，操作区不承载观测。** 最容易被破坏、最需反复检查的一条。

---

## 一、骨架与视角

```
┌─────────────────────────────────────────────────────────────┐
│ ① 标题栏                    视角：系统（非产品设计）          │
├──────────┬──────────────────────────────┬───────────────────┤
│          │ ② 会话头    视角：会话级      │                   │
│ ③ 左栏   ├──────────────────────────────┤ ⑦ 右栏            │
│ 视角：   │ ④ 会话流    视角：会话级/时间 │ 视角：外部世界     │
│ 全局     ├──────────────────────────────┤                   │
│          │ ⑤ 输入区    视角：会话级      │                   │
│          ├──────────────────────────────┤                   │
│          │ ⑥ 状态栏    视角：运行态      │                   │
└──────────┴──────────────────────────────┴───────────────────┘
```

**结构概括**：**导航 | 叙事 | 现场**——左栏是**入口**（去哪、做什么），中栏是**主线**（你和 agent 的过程），右栏是**副产物**（agent 干活时外界的样子）。

## 二、区域定义与规则

### ① 标题栏 · 系统级

| 项 | 内容 |
|---|---|
| **回答** | 我在哪个应用、能否操作窗口 |
| **承载** | 侧栏开关、搜索、菜单、窗口按钮 |
| **禁止** | 任何产品功能 |

- **规则 ①-A**：这里的一切属于操作系统 / Electron 层面，设计决策不在此处做。
- 现状不一致（主题切换、「改动」、「设置」在此）见 §四 #1。

---

### ② 会话头 · 会话级标识

| 项 | 内容 |
|---|---|
| **回答** | 我在哪个任务里？哪些操作是对**这个会话**本身的？ |
| **承载** | 任务标题、会话级操作（分享、复制）、会话上下文（cwd / 分支）、会话级显示入口（统计 / 规则 / 搜索 / 只看问答） |
| **禁止** | **运行态操作**（停止 / 暂停）、**发送参数**（模型、权限模式） |

- **规则 ②-A**：判据是「这个操作在会话不运行时还成立吗？」成立（分享、复制）→ 属这里；不成立（停止）→ 属 ⑤。
- **规则 ②-B**：会话**上下文**（工作目录、分支）必须在此可见。它显示**这条会话自己的**工作目录（由 `SessionInfo.projectId` 反查项目 rootPath），不是「当前选中的项目」——两者只在切项目的那个 IPC 窗口里短暂错开，取后者会显示一个这条会话根本不用的目录（v1.46 收成单一真源）。
- **现状**：cwd + git 分支 chip（游离 HEAD 转琥珀、窗口获焦刷新）；**入口只剩「统计」「规则」两个**——v1.30 由「改动 / 用量 / 工具 / 规则」四收敛为二（「改动」改由 ⑦ 总账进下钻，「工具」并入「统计」）。另有两个**会话级显示入口**：「**搜索**」（原「目录」；v1.45 起目录改由 ④ 左缘点链承担，浮层只留搜索）与「**只看问答**」（整轮折叠，见 ④-E）。它们与「统计 / 规则」不同——不打开右栏、只调本会话的呈现，但同样满足本区域判据。
- **例外**：会话头保留的「压缩上下文」按钮（上下文 >70% 才出现）与 ⑤ 的 `/compact` 是**刻意的双入口**（一处预警式、一处命令式）——见 §四 #2。

### ③ 左栏 · 全局导航

| 项 | 内容 |
|---|---|
| **回答** | 我能去哪？我有哪些任务？ |
| **承载** | 模式切换、功能入口、项目 / 任务列表、用户区 |
| **禁止** | 会话内的任何状态 |

- **规则 ③-A**：L1（模式：Work / Code / Design）与 L2（导航：新建任务 / 插件市场 / 模板库 / 自动化 / 办公助理）语义不同，**不可同权重并列**。**状态（2026-09）**：L1 / L2 均为计划中功能、尚未实现，本规则**暂无适用对象**；当前左栏是「项目 → 会话」两层列表 **+ 会话分支树面板**（下半区，按会话展示分支、可点击跳转，`features/BranchTree.tsx`），待功能落地时再执行本规则。
- **规则 ③-B**：任务列表是**跨项目、跨会话**的，属全局视角，不随当前会话变化。
- **规则 ③-C**（v1.46）：**侧栏只列已落库的会话**。「还没用起来」的草稿不在其中——判据是「这条会话真的存在过吗」：`session.list` 只读库，而草稿（首次发消息才落库）读不到，故「点了新建又没发消息就退出」不留痕迹。反向的时效要求同样算在这里：首次发消息落库后要**立刻**出现在侧栏——由主进程的**进程状态推送**触发一次列表刷新（草稿落库先于拉起 worker，「有了进程」等价于「已落库」），**不依赖模型是否回话**（模型连接失败也必须看得见）。离开时丢草稿走 `session.discardDraft`（只在仍是草稿时生效），不用 `session.delete`——后者会真的删库。
- **现状**：运行中会话的**绿点与计时挂在会话行上**（`App.tsx` 的 `SessionRow`），**不在 `BranchTree` 里**。

### ④ 会话流 · 叙事主线（核心区域）

| 项 | 内容 |
|---|---|
| **回答** | 我们聊了什么？它做了什么？ |
| **承载** | 思考轨、用户消息、Agent 回复、**工具卡**（内嵌 diff）、授权卡 |
| **顺序** | **严格按时间线性排列** |
| **禁止** | 非本次会话的信息、跨会话汇总 |

**必须承载的信息类型**（每类一个组件）：

| 类型 | 组件 | 来源 | 优先级 |
|---|---|---|---|
| 推理过程 | 思考轨 | `ThinkingRail` / `ThoughtBlock` | P1 |
| 正式回复 | Markdown | `Markdown` | P0 |
| **工具调用** | **工具卡** | `ToolCard` | **P0（最高频）** |
| 子代理委派 | **子代理卡**（`ToolCard` 的特化形态） | `MessageList.tsx` 的 `ToolCard` + `SubagentPreview.tsx` | P1 |
| 权限阻塞 | 授权卡 | `ApprovalCard` | P0 |
| 文件变更 | **工具卡内嵌 diff** | `MessageList.tsx` 的 `ToolCard` | P1 |
| **技能调用** | **技能卡**（折叠，展开看模型实际收到的正文） | `MessageList.tsx` 的用户消息分支（`data-conv-skill`） | P1 |

> **订正**：此处原写「变更卡 / `ProjectChanges`」。`ProjectChanges` 实为**主区整页**（项目级、跨会话汇总，由 ① 的「改动」打开），**不在 ④**（④ 禁止跨会话信息）。④ 里承担「文件变更」的是**工具卡内嵌 diff**，它也是「点文件路径 → 下钻预览」的入口。

- **规则 ④-A**：**信息密度必须可调**。工具卡默认折叠成一行（图标 + 名称 + 路径 / 命令 + 增删 + 耗时 + 状态），展开才显示 diff / 输出 / 截图。依据：自用场景要「扫一眼知道发生了什么」。
- **规则 ④-B**：**叙事顺序不可打乱**。推理在结论前、工具调用在结果前、授权卡在它阻塞的那个时刻。
- **规则 ④-C**：工具卡是**出现频率最高**的元素（每轮多个），其设计质量直接决定「能否看懂它在干嘛」。**不可省略、不可简化成一行纯文本**。
- **规则 ④-D**：工具卡图标必须**语义化**（read / edit / bash / browser / computer 各不同），不可统一用扳手。
- **规则 ④-E**（2026-09）：「**只看问答**」。④-A 只管到「逐卡」；一轮十几个调用就是十几行，回看时正文仍被中间步骤淹掉。故把一轮的**过程**（思考 + 全部工具卡）收成一行、点开再展开，只留提问与最终回复（分组见 `lib/turn-groups.ts`，纯函数有单测；渲染在 `MessageList.tsx` 的 `MessageWindow`）。三条硬约束：① 入口在 **②**（会话级显示选项），**默认关**——它改变的是「每次打开看到什么」，而工具卡是叙事的一部分（④-C），不该由产品替所有会话决定收起来；② 收起的那一行**必须是可展开的入口**（「不可省略」不等于「可以删掉」）；③ 判据是**折叠前后提问与最终回复一条不少**（冒烟 `perf` 按行标记逐条核）。
  - **窗口单位跟着折叠走**：不折叠时数**条**消息，折叠时数**轮**——折叠后一轮只占两三行，继续按条数会把窗口吃光，而点这个开关的人要的恰恰是**多读几轮问答**。窗口起点**按单位各记一份**：进折叠时把「条」换算成「轮」（`turn-groups.ts` 的 `turnOfMessage`），展开时把「条」那份**原样还回去**（关掉开关看到的就是打开之前那一屏）。算术见 `lib/message-window.ts` 的 `FOLD_CHUNK`（有单测），两份起点在 `MessageList.tsx` 的 `heads`。
- **规则 ④-F**（2026-09）：**跳到某一轮必须落成「浮动段」**。消息窗口原只有两态——跟最新、或从某点**一直挂到末尾**；用后者跳会一次挂出「目标 → 末尾」几千条，正是窗口要防的事。第三档是**只挂目标那一小段**，上下各能翻页；**翻到底要交回「跟随底部」**，否则之后流式追加的新消息会全落在窗口外，表现为「明明已在最新处，界面却不再更新」。算术见 `lib/message-window.ts` 的浮动段一节（有单测），冒烟判据取「跳过去之后**挂载数仍是一个窗口**、且尾行**不等于**末尾」。
- **规则 ④-G**（v1.45）：**轮次点链挂在 ④ 左缘，是「会话目录」的常驻化**（`TurnRail.tsx`）。此前目录是 ② 浮层里的一半，点开浮层才能跳轮；v1.45 起收成左缘的**点列**——离开顶部才浮现、默认可见 11 个点、轮次更多时 rail 自己滚（`overscroll-contain`，滚到头不带动会话滚动，滚动条隐藏）、悬停展示第 N 轮 + 提问摘要、当前点跟着会话滚动走。两条语义边界：① 点链是**目录**不是分支树——只有一条线性点列、没有分叉；点击走 `history.jumpTo`（**只读定位**，落成 ④-F 的浮动段），**绝不做** `session.navigate`（那是分支树的分叉语义，会改会话本身）。② 数据全在渲染层（`outlineOf` / `turnAt`，有单测），零新 IPC。冒烟判据在 `perf` 模式「六」段。
- **规则 ④-H**（v1.49）：**子代理的卡是工具卡的特化，不是新组件。** `subagent` 是模型的一次工具调用，所以它天然属于 ④ 的工具卡（④-C：不可省略）；特化只加三样——图标换 `Bot`、标题写成「**子代理 · <定义名>**」、状态标签单独标（`data-subagent-card-status`）。展开区里给**有界预览**（`SubagentPreview.tsx`：最近 N 步 + 流式文本 + 思考 + 运行中的工具 + 统计），并**如实说明截断**（「最近 12 步（共 20 步）」——静默砍掉会让用户以为它只跑了 12 步）；**顶部**给「**在右栏查看完整过程**」这个下钻出口——入口排在预览**之前**：预览动辄十来步，排在末尾等于把唯一的深看出口埋掉（冒烟按 DOM 顺序钉住）。**卡随 transcript 长生**：子代理跑完了卡还在（那是这次委派发生过的事实），只是卡上的运行态标记转成完成、卡上的「中止」随之消失（v1.53 前那是「此刻段」那一行的事）。**默认收起**（v1.60 起）：与普通工具卡「运行中默认展开」相反，子代理卡**一律默认折叠**——它的展开区（有界预览 + 深看出口）动辄十来步，跑起来时摊开会把主对话顶得很长；用户需要时自己点开，运行态/完成态由卡面的状态徽标表达，收起不丢信息。展开状态仍归 ④ 的共享表 `toolOpenState`，用户点过就记住。
- **规则 ④-I**（v1.54）：**技能调用不冒充用户发言**。内核把技能正文包成**一条 `role: "user"` 消息**（正文是 `<skill name="…" location="…">…</skill>` 原始 XML），但它**不是用户说的话**——署名不能是「你」，整篇正文也不该摊在对话流里。判据取 `ViewMessage.skill`（worker 投影时用 `parseSkillInvocation` 认出内核 `formatSkillInvocation` 的**固定开头两行**，**不是**渲染层再拿字符串去猜），命中则画成左对齐的可折叠**技能卡**：卡面写「技能 X · 本会话装载，非你的发言」+ 那半句额外指示，正文默认收起、`data-conv-skill-toggle` 展开——**展开是「归属透明」的出口**（用户有权看到模型实际收到了什么）。② 会话目录与 ③ 分支树的标签 / 摘要改用单一真源 `skillInvocationLabel`（仍是「技能 X[· 指示]」），不再出现原始 XML。它**仍算一轮**（用户确实敲了这条命令、它也确实换来一次回复），被改的只是**归属**。正常用户气泡补 `data-conv-user` 作对照——冒烟据「有技能卡且无用户气泡」判改归属真的发生。
- **规则 ④-J**（v1.56）：**模型「自己想起来用技能」必须留下痕迹**。模型不会「调用技能」——它读了技能描述后自觉去 `read` 技能文件（内核没有 skill 工具，见 `reviews/skills-gap-report-2026-09-19.md` A4）；不标记的话，界面上只会多一张普通 `read` 卡，看不出「这次读文件是技能驱动的」——而这恰是最该被观测的一件事（它决定模型怎么干活）。故命中「本次 `read` 的路径 = 某已装载技能的文件」时，工具卡上打一个「**技能 X**」徽标（`data-tool-skill`）。两条边界：① 判定在 **worker 投影时**做（技能路径集合就在它内存里，`skillPathMatcher`），渲染层**不重算**路径规则——两处各算一套必然漂；② 徽标是**追加**的，不改工具卡既有形态（④-C 不可省略、④-D 图标语义化照旧）。

### ⑤ 输入区 · 交办

| 项 | 内容 |
|---|---|
| **回答** | 我要它干什么？**用什么参数**？ |
| **承载** | 输入框、附件、**模型选择**、发送 / 停止 |
| **禁止** | 运行状态观测（那属于 ⑥） |

- **规则 ⑤-A**：判据是「这是**发送这条消息的参数**吗？」是（模型）→ 属这里；不是（上下文占用、心跳）→ 属 ⑥。
- **规则 ⑤-B**：**停止 / 中断**属于这里。理由：它是「控制本次运行」的操作，与「发起本次运行」（发送）同源。
- **规则 ⑤-C**：窄宽度时**先折叠文字标签，再考虑换行**。发送按钮永不收缩、永不被挤出。
- **规则 ⑤-D**（2026-09 修订）：**权限（审批）模式在此区域呈现**——它属于「发送这条消息的参数」（同 ⑤-A），位置是输入工具行右侧的下拉。历史：曾写作「暂不在此区域呈现」，后由实现确定归属。
- **规则 ⑤-E**（v1.44）：**斜杠命令的候选浮层**属于这里，且**必须是浮层、不占工具行的常驻宽度**。理由有二：一是 ⑤-C 已规定工具行在窄宽度下的行为，而那一行已有 4 个控件、还带着一条「卡片不能被裁」的回归，再挂一个常驻控件等于把问题推给它；二是命令的**名字本来就要打在输入框里**，提示贴着输入框长才自然。硬约束：**浮层只在候选真的存在时才出现**——否则用户每次贴 `/usr/local/bin` 这类路径都会被一个空菜单打扰。
- **规则 ⑤-F**（2026-09）：**斜杠命令共三条，分两类语义**，判据全在 `lib/slash-command.ts`（纯函数、有单测）。
  - **零参数**：`/compact`（压缩上下文）、`/memory-tidy`（整理沉淀的记忆）——必须**独占整条输入**（`"/compact"` 或带尾空格都算，`"/compact 一下"` 不算），**不做前缀匹配**；否则用户想发「用 /compact 手动压缩」这句正文会被当成命令吞掉（v1.34 的教训）。
  - **带参数**：`/skill <名字> [额外指示]`——只能前缀匹配，故加两道阀限制代价：命令字须**整段等于** `skill`（`/skills`、`/skillfoo` 都不是命令），且后面须真有**非空名字段**。
  - 名字不存在时**不回落成普通消息**，而是**就地拦下**并给出同一句话（文案在 `@shared/skill-error`，渲染层与 worker 共用同一份）——「敲了没反应」比报错更伤信任。
  - 名单**来源**是本会话的 `ConversationView.skills`（v1.53 起是整份 `ViewSkill[]`，渲染层只取 `name`）。⚠️ 拿不到视图时它是 `undefined` ＝ **不知道**，必须**放行**——当「空的」会把一次有效调用误判成失败，那是另一种丢输入。
- **规则 ⑤-G**（v1.46）：**没有会话也要能交办**。项目在跟前、却一个会话都没有时，输入区**照常在场**（为此自动建一条**草稿**：只分配 id，不落库、不 fork worker、不建 JSONL）。理由：输入区是「交办」的唯一入口，把它藏在「先新建会话」后面，第一屏就只剩一块**只能看的空屏**。自动建草稿同时满足 ③-C，因此「见得到输入框」与「侧栏不留空会话」两件事可以同时成立。反向约束：中间区**不再出现「新建一个会话开始对话」这类指路文案**——入口本身就是输入框。
  - 判据是纯函数 `shouldOfferDraft`（`lib/session.ts`，有单测）：三件事必须分开——列表还没到（`undefined`）要**等**、有落库会话就不必给、当前已是本项目的一条（含草稿）就不能再给（否则会无限建）。
- **规则 ⑤-H**（v1.47）：**起手态把「提示块 + 输入卡片」一起上移到相对中间**，并且**只有起手态才提供改目录的入口**。
  - **排布**：没有任何消息时，左列换成「会话头 / 0 / 1fr」——输入列拿到第 3 行的整块高度，用 `justify-center` 把两块**一起**居中（`StartPanel.tsx` 是提示块，`Conversation/index.tsx` 的输入列是输入卡片；两块在**同一列里上下相邻**，不是父子）。有消息后回到「消息流占满、输入区贴底」：贴底是**交办**的常态。起手态的判据是 `empty`（没消息 + 没在启动 + 没报错 + **没有待办提示**）——最后一项不能省：「还差一步配密钥」那条黄条住在消息区里，而起手态要把消息区收起来，不排除它就会把黄条一起藏掉，等于**静默失败**（见 `ERRORS.md`）；宁可这时不显示起手提示块。
  - **输入卡片的宽度由「可用宽度」决定，不由内容撑**（v1.60 修）：外层是 `mx-auto w-full max-w-[796px] px-[18px]`——**`w-full` 不能省**。起手态的输入列是 flex 列，`mx-auto` 的跨轴 `auto` 外边距会打断 flex 的 stretch，少了它卡片就按内容收缩（实测中栏 642px 时只有 445px，比它上面的提示块还窄）。成立时宽度 = `min(796, 中栏宽) − 36`，与消息列（`max-w-3xl`）基本对齐；这条有冒烟哨兵（拖右栏把中栏压到 360 后按公式逐像素核）。
  - **起手态的空输入框固定 3 行高**（v1.60）：`min-h-[73px]` ＝ 3×行高(20.3125) ＋ 上下内边距(12)。这条同时是「不高不矮」的两条线——矮了写不下一句话，高了就是「有点太高」。⚠️ 该高度只在**行高没变**时才等于 3 行：起手态往 `textarea` 上加字号类（如 `text-[13px]`）会让 tailwind-merge 把 `leading-relaxed` 当冲突项**静默删掉**，行高退回继承来的 1.5，同一个 73px 就不再是 3 行。冒烟用两条断言守：**行数 = 3**、**行高 = 1.625×字号**（都按元素自己的计算样式现算，不写死像素）。
  - **目录只在起手态可改**：`<工作目录> + [换一个目录] [新建工作目录]`，后两个是**图标按钮**（`FolderOpen` / `FolderPlus`，见 v1.60）。发完第一条消息目录就定死了（`project_id` / JSONL 目录 / worker 的 cwd 全按它，换目录等于换会话），所以不做成常驻控件；平时要看目录的地方是 ② 会话头。
  - **「换一个目录」= 换项目**（`project.pick`）：`sessions` 表**故意不存 cwd**，「读项目内文件」的根与记忆隔离键（`normalizeRootKey`）都由项目根推出——会话级 cwd 会一次牵动三处消费方，按换项目实现是零成本的。
  - **「新建工作目录」= 主进程造一个**（`project.createScratch`）：`~/.colt/<年月日-时分秒>/workspace`——父目录沿用仓库既有的**用户级命名空间**（用户级记忆就是 `~/.colt/memory.md`，见 `worker/lib/memory.ts`），家目录里只开这一个口子；时间戳精确到**秒**（两次不同时刻的意图必须拿到**两个**目录——只到分钟时一分钟内点两次会落到同一个已装东西的目录，「给我一块干净的地方」当场落空；同一**秒**内重复点才落到同一路径、由 `upsertProject` 按 root_key 去重）。最里层的 `workspace/` 才是**项目根**（名字固定，时间戳那层留给这一次的日志与产物）。落在**家目录**（而非应用数据目录）是因为它是**用户的工作产物**，必须找得到。`COLT_WORKSPACE_ROOT` 非空时原样使用（冒烟靠它钉在 `out/smoke-workspace`）。
  - **目录属于「项目」，不属于「会话」**：多条会话可共用同一工作目录（同一项目下点「+」开的第二条会话与第一条同目录）；「新建工作目录 / 换一个目录」换的是**当前这条草稿**的归属（换项目），别的会话原地不动。
  - **分支只显示、不切检出**：`git.ts` 只读 `.git/HEAD`，仓库里没有任何 git 写能力；「选分支」等于新引入「检出」这条写路径，故先不做——要换分支就交给 agent（它有 bash）。② 会话头的分支徽标照旧只读。
  - 锚点：`data-conv-start` / `data-conv-workdir` / `data-conv-newdir`；另 `data-conv-card`（输入卡片，探针按它认，别用 `parentElement`）、`data-conv-session`。

### ⑥ 状态栏 · 运行态观测

| 项 | 内容 |
|---|---|
| **回答** | 现在什么情况？**它还活着吗**？ |
| **承载** | 上下文占用、成本、心跳（已耗时 + 最后活动）、stale 警告 |
| **禁止** | **任何操作**（按钮、开关）、发送参数 |

- **规则 ⑥-A**：**只读区不放操作。** 本区域最容易被破坏的规则。反例：曾有中断按钮、模型选择器、会话级模式选择器置于此，均已移除。
- **规则 ⑥-B**：**必须每秒走字**。心跳的意义在于「数字在动 = 它活着」；停止走字本身就是信号。
- **规则 ⑥-C**：**超时不许伪造活动**。超过阈值无事件时**如实**提示，**不可用转圈动画假装在忙**。实现口径：心跳常显「最后活动 Ns 前」；超过 `STALE_IDLE_SEC = 30` 秒无事件时该读数转琥珀，并追加「似乎卡住了，可中断」。提示的是「没动静」这件事本身，不把它改写成「还在忙」，也不给用户一个假的进度。
- **规则 ⑥-D**（2026-09 落定）：运行态之外**必须给出明确的状态**，不留空。状态段由 `running` + 最近一轮终态（`ConversationView.lastRun`）推出，共四态：运行中（绿点脉动）/ **已中断**（灰点 + 文案）/ **已失败**（红点 + 文案 + 一行截断的 error 摘要，悬停看全文）/ **空闲**（灰点 + 「空闲」）。
  - 只有**中断**与**失败**单独留一行：正常跑完（`completed`）与「还没跑过」一样回到「空闲」——状态条不该为一次正常的结束留痕。判定是纯函数 `lib/format.ts` 的 `runStateOf`（有单测）。
  - 终态取内核 `LaneSnapshot.lastResult` 且**只认 `kind === "run"`**（压缩 / 导航的终态不答「我交办的事」这一问）。**别用 `faulted`**：那是 harness `fault` 事件的会话级硬故障、内核从不复位它（该字段已从 `ConversationView` 删除，见 `ERRORS.md`）。
  - 状态是**电平**：结束态一直留到下一轮跑完，不是一闪而过的提示。颜色只是**辅助**，每个态旁边都有文字（「颜色必须配文字」）。
  - 已知限制：`lastResult` 是 lane 生命期的记录，worker 被空闲回收后重建（切会话 / 重启）会丢 → 回落成「空闲」。
- **规则 ⑥-E**：位置在**输入区下方**。理由：与「交办」动作相邻，发完即可观察状态。

### ⑦ 右栏 · 工作区（Workspace）

| 项 | 内容 |
|---|---|
| **回答** | Agent 正在操作的**对象**长什么样？以及我想看的任何附属内容 |
| **定位** | **一个可插拔的容器**，不是某个专用栏 |
| **默认视图** | **任务摘要**（计划进度 + 此刻在跑什么 + 本次改动总账） |
| **其他视图** | 浏览器、阅读器、文件……**不限个数** |
| **宽度** | **由用户拖拽决定**（220px ~ 窗口中栏留 360），视图切换不覆盖 |
| **禁止** | 会话叙事（那属于 ④） |

**定义要点**：右栏**就是工作区**，「任务摘要」只是它的默认视图。

| 视图类型 | 内容 | 对应疑问 |
|---|---|---|
| **任务摘要**（默认） | 计划进度（将来）+ 此刻在跑什么（现在）+ 本次改动总账（过去），后者下钻清单 → diff → 内容 | 这件事进行到哪了 |
| **外部世界** | 浏览器页面、URL、console / network / downloads、用户自己的前进 / 后退 / 刷新、装不下时的「适应宽度」 | 它在网上操作什么 |
| **阅读** | Markdown / 文本阅读器 | 我想看什么内容 |
| **文件** | 系统文件浏览 | 项目里有什么 |
| **附属内容** | 会话统计（原「用量历史」）、审批规则 | 这次会话花了多少、被放行 / 拦了什么 |

#### 代码现状与范围（2026-09）

- **页签只有五个 kind**：**任务摘要（默认，kind 仍为 `follow`）/ 浏览器 / 统计 / 规则 / 事件**（`WorkspaceDock.tsx` 的 `DOCK_KIND_META`；「事件」是 F3 安全事件流的回查页签，v1.50）。
- **「阅读 / 文件」的范围已收窄**（决定见 `NEXT-PHASE.md` A3）：**不做整项目树**——右栏是「现场」，「项目里有什么」是 IDE 的问题。落地形式是**「点文件路径 → 预览」**（A3-2）：入口是 ④ 工具卡的副标题（**仅当副标题就是该工具操作的文件时**才可点，判定用「展示文本 === 路径」而非「有 `path` 参数」，避免 `grep` / `glob` 的搜索模式被误当文件）。
- **预览按类型分流**：`.md` 走 Markdown 渲染；其余文本按扩展名认语言（`renderer/src/lib/code-lang.ts`）后交 highlight.js 着色 + 左列行号，**认不出就原样等宽、不猜**；图片给 dataUrl、二进制与过大只给提示（不做半截渲染）。语言映射只列 common 包里注册过的语言（由单测逐条核对）。
- **⑦-G 第四步（v1.32）之后这些内容不再各占页签**：预览是「任务摘要」下钻的**内容层**；原先「范围 A：本次动过的文件」那棵树（A3-4）升级成同一处的**清单层**——按目录**一层**分组（不是可折叠树），同一文件多次编辑折成 `×N`，行上带 `+a −b`；清单只列 `fileChanges` 且**排除不可预览的越界路径**，并把隐藏了几条如实写在底部（约束 ⑦-4）。`styles.css` 里原「文件」视图的 `.file-view` / `fv-tree` 随之删除。
- **页签模型是「实例列表 + `activeId`」**（A3-1）；**页签可关闭 + 「+」新增视图**（A3-3）——「可关闭」与「菜单里能打开」是**同一集合**（清单由 `closable` 推导），故结构上不存在「关了回不来」；菜单**只列产品里真有的视图**（现为 `browser / usage / rules / events`；终端仍未实现，不入菜单，避免死菜单项）。
- **两个观测 / 管理面板已迁入本容器**（A3-5）：「统计 / 规则」由**中栏浮层**改为 ⑦ 的**可关闭页签**——依据正是本栏定义里的「**以及我想看的任何附属内容**」与「其余视图不限个数」。迁入后**只有页签这一个载体**：面板自身不再有「收起」（关闭交给页签的 ×），② 的两个入口与「+」菜单都只是打开同一页签的快捷方式。
- **浏览器页签底部有「观测抽屉」**（B2）：控制台 / 网络 / 下载三份观测。它读主进程 `CaptureBuffer`——与 agent 的 `browser_read` **同一份**缓冲，不存在「界面说的和模型看到的不一样」。抽屉**属于浏览器视图内部**，不另立页签（它回答的是「这个页面怎么了」，脱离页面就没意义，与 ⑦-C 一致）。抽屉占页面区域的高度，收起 / 展开经 ResizeObserver → `browser.bounds` 同步给原生视图。**行是概览，点开才是全貌**（v1.33）：点一行在下方展开「字段表 + 复制」，`URL` / 路径上的原生 tooltip 随之撤掉；字段映射抽在 `lib/observe-detail.ts`（纯函数，有单测），详情段落带自动滚入可视区。
- **浏览器页签顶部有「后退 / 前进 / 刷新」**（B1）：由**用户**发起，与 agent 的 `browser_act` 是两条链路——那条走审批（裁决的是模型给出的入参），这条没有模型参与、没有可裁决的对象，**不走审批**；何况内嵌页是真实 `WebContentsView`，用户本来就能直接点它。按钮可用性来自主进程现读的 `navigationHistory`（渲染层不自己记历史，那必然与真实 webContents 走偏）。页面被换掉后 agent 的判断会过期，故同时**告知 agent**：经 `browserNotice` → worker 在下一次模型请求前用 `transform_context` 注入环境提示（不写进 transcript），且**只在 agent 正在跑时**转发。详见 `NEXT-PHASE.md` B1。
- **原生视图的矩形每 400ms 重申一次**（窗口不可见时暂停，v1.51）：视图必须**一直**等于「页面区域」，而 ResizeObserver / window resize 都是**边沿**触发——漏一次边沿就永久错位（实测：抽屉再展开时页面区域矮了 132px，视图却停在收起时的高度，于是压住观测抽屉）。冒烟按「**逐像素**对齐 + 反复收起 / 展开 5 轮」验。
- **视口联调覆盖会在头部显形**：`browser_act viewport` 设的尺寸是**持久**状态（只在显式「恢复」时撤销），且会让原生视图比停靠区更大（实测覆盖 1280×800、停靠区 823×643 时，右侧 209px 被窗口边缘裁掉、下方 157px 压住观测抽屉）。现在头部显示 `视口 1280×800 · 恢复`（`data-browser-viewport` / `data-browser-viewport-reset`），未被视图盖住的页面区域改用中性底。**「适应宽度」**（v1.40）把整页等比缩小到刚好装下：只改页面 CSS 视口（`setZoomFactor`），**不动原生视图矩形**，故逐像素对齐不受影响；比例钳在 `[MIN_FIT_ZOOM, 1]`（可读下限 60%），顶到下限仍装不下就如实说并**撤掉按钮**；「还原」出口常驻工具条；`contentWidth` **只在 `zoom === 1` 时量**。

- **规则 ⑦-A**：⑦ 是**「现场」**，④ 是**「叙述」**。④ 说「我点了登录按钮」，⑦ 展示那个按钮本身。两者是同一件事的两种表达，**不可互相替代**。
- **规则 ⑦-B**：**⑦ 是工作区容器，不是浏览器专用栏。** 以**页签**切换视图；「任务摘要」是默认视图，其余视图**不限个数**。
  - **宽度只由用户拖拽决定**，且是**全局统一值**——**不随页签变化**。依据：原按视图类型各给建议值（任务摘要 300 / 浏览器 544 …），于是切页签就改宽度，中栏跟着忽宽忽窄、内容反复重排，是纯粹的视觉噪声。现在未拖拽时一律取 `DOCK_DEFAULT_WIDTH = 544`（取各类视图里较宽的那个需求；v1.24 前那条「『文件』双栏树要求 ≥520」的依据已随 v1.32 失效，现依据是**下钻的 diff 与文件预览需要横向空间**）。
  - **代码现状**：拖拽把手**已实现**（`Conversation/index.tsx` 的 `.dock-grip`，9px 命中区浮在两栏分隔线上，双击复位）。宽度取 `用户拖拽值 ?? 统一默认宽度`，并钳制「右栏 ≥ 220px、中栏 ≥ 360px」；窗口缩放时按当前可用宽度重新钳制。拖拽位移只对**位移**取负（`startWidth − dx`），见 `AGENTS.md` 3.3。本规则已完整成立。
  - **「浏览器」按需加载**：未用到时不创建 WebContents（对齐 `browser-host` 的懒创建）。
- **规则 ⑦-C**：**视野跳跃必须为零。** 任何需要用户「在另一个窗口里找」的设计都是错的。依据：外部窗口会破坏 ④ 与 ⑦ 的并置关系。
- **规则 ⑦-D**：⑦ 的更新**不可抢焦**（不改变用户正在读的 ④），仅静默更新自身内容。
- **规则 ⑦-E**：**默认视图必须是「任务摘要」，且不可关闭（但可折叠）。** 理由：自用场景下，「这件事进行到哪了 + 它正在碰哪些文件」是判断安全性的第一依据，必须常驻可见。折叠态收为 44px 图标条（保留页签与活动指示），**不提供完全关闭**。
  - **更名（v1.48）**：本视图此前叫**「正在处理」**，补上**计划**那一段后覆盖面变成「将来到过去」，而「正在处理」只答得了「此刻」——故更名**任务摘要**。`DockKind` **仍是 `follow`**（kind 是内部标识，改的只是标签与定义）。同批必须改掉两处**别处的同名字样**（`ChangeDrilldown` 的面包屑与「返回…」文案、`dock` 冒烟里按标签断言的用例），否则会出现「页签叫任务摘要、面包屑叫正在处理」。
  - **代码现状**：折叠态已实现——页签行左端为折叠旋钮，折叠后收为 44px 图标条；折叠态**不渲染**拖拽把手，且**同步收起原生浏览器视图**（`showArea = 浏览器页签 && !collapsed`，折叠即上报 `null`）。折叠态点图标条上的视图入口 = **切到该视图 + 展开**（44px 里只切不展开等于点了没反应）。
  - **「它是活的吗」判据的归位（v1.53）**：这条判据原先落在「任务摘要」的「进行中的动作」段上（面板必须能显示「空」）。该段已删除——它逐条列 `runningTools`，与 ④ 的运行中工具卡（含输出 / diff / 截图）重复；又因为它是 `flex-1`，会把剩余高度全吃掉，把**计划**挤进 `max-h`、把**总账**顶到面板最下沿。现在这句话由 **⑥ 状态栏**（⑥-D 四态：运行中 / 已中断 / 已失败 / 空闲）+ ④ 的运行中工具卡回答。
  - **不可关闭是规则，不靠「碰巧没人调用」保证**：默认视图**不渲染关闭按钮**，且 `closeDockInstance` 里有 `isDockClosable` 守卫。可关闭的视图现为 `browser / usage / rules / events`（其余 kind 由 `closable` 推导成「+」菜单项），出口有两条：`+` 菜单、⑦-F。
- **规则 ⑦-F**：**agent 开始操作某个视图的对象时，自动切到对应视图。** 具体：agent 首次使用浏览器 → 右栏自动切到「浏览器」页签。**优先级**：此场景下 ⑦-C（视野跳跃为零）**优于** ⑦-D（不抢焦）——agent 开始用浏览器 = **新现场的开始**，必须被看到；用户随时可切回其他页签。
  - **代码现状**：若右栏当时处于折叠态，自动切页签的**同时展开右栏**（只切页签而右栏还收着，等于没被看到）。
- **规则 ⑦-G**：**改动清单不另立视图，它是「任务摘要」的下钻；总账是「任务摘要」的一行。**
  - 「任务摘要」由**两段**构成，两个时态、互不重复（**顺序即阅读顺序**）：

    | 段 | 时态 | 内容 | 独有性 |
    |---|---|---|---|
    | **计划**（v1.48 新增） | 将来 | 待办清单：`N/M` 进度 + 进行中那条（带 `activeForm`）+ 待做；**已完成折成一行「已完成 N 项」**（点开看） | **全应用唯一出处** |
    | **本次改动（总账）** | 过去 | 一行：`N 处 · M 文件 +a −b`，**紧跟计划**，点击进入清单 | **全应用唯一出处** |

  - **v1.53 删去「进行中的动作」段**：它逐条列 `runningTools`，与 ④ 的运行中工具卡（含输出 / diff / 截图）重复；且它是 `flex-1`，会把剩余高度全吃掉——清单被挤进 `max-h`、总账被顶到面板最下沿。此刻动作**只在 ④**，「它是活的吗」由 ⑥ 回答（见 ⑦-E 的归位）；子代理的「中止」随之挪到 **④ 的子代理卡**（`ToolCard`）上，**只在 `status === "running"` 时出现**（已结束的卡上不放点了没反应的按钮）。
  - **本规则真正的不变量是「同一类对象只在一处渲染」，不是字面上的「几段」。** 它当初要消除的是**同一个 `fileChanges` 被渲染三遍**（`FollowPanel` 段一 / 段二汇总 / `ChangesPanel` 列表）；计划与改动是**两类不同对象**，各画一次故不违背本规则。反过来两条约束仍然有效：① **不得把「计划」再抄一份到别的视图**（② 已决定**不加**常驻进度入口）；② **不得把两段并成一个大列表**——时态会混在一起。
  - **计划段的清单不设自己的滚动上限**：清单多长就多长，超出面板高度由**本视图整体**滚动，不在半截处截断（曾写死 `max-h-[45%]`，清单略多就只在自己那一小块里滚）。
  - **总账不是视图，不另立页签，也不钉在右栏底部**：它属于「任务摘要」，**紧跟计划**、跟着该视图出现、随切页签消失（那一刻用户在别的现场，「这次会话改了多少」不是他要看的）。总账由「可折叠区段」降级为**「一行状态」**（不是 `fsec`，没有 caret / 展开态 / 空态）。
  - **「处 / 文件」两个数都必须显式命名**：总账写「**N 处 · M 文件**」——「处」是改动条数（`fileChanges.length`）、「文件」是去重后的文件数。**两个口径确实不同**：总账用**原始**计数（含项目外条目），清单头部用 `buildChangeList` 的**过滤后**计数（排除项目外）；`±` 只在清单侧算且给的是**净值**（v1.36）。这不是缺陷（各有理由），但**不能再写「一个口径」**。
  - **「任务摘要」→ 清单 → diff → 文件内容是一个东西的连续下钻**，层级用面包屑表达，ESC 逐层回退。用户不需要知道「该去改动页签还是文件页签」，只需要知道「想看得更细」。
  - **下钻目标从「文件内容」多了一种到「子代理流」**（v1.49）：点 ④ 子代理卡上的「在右栏查看完整过程」→ 落到**子代理流层**（`SubagentStream.tsx`，面包屑 `子代理 · <名字>`）。它与改动那条线是**并排的两种目标**：进入它不经过清单，回退**直接回「任务摘要」**。视图里只带**有界尾部**，完整流**按需拉**（`session.subagentTranscript`，10s 超时）；拉不到时**如实说「还没有留下过程记录」**，不白屏、不假装有内容。**这一层按状态分两个真源**：**运行中**走视图通道（跟着实时刷新，但只有视图带的**最近几步**，并在那一层**明说**这一点，不假装完整）、**跑完之后**才换成拉回来的完整流——一次性快照拉回来就**静止**了，而子代理还在动，用它渲染会造成「概览（④ 卡）比详情新」（v1.52）。
  - **代码现状**：①② 在 v1.29 落地（`FollowPanel.tsx`）；③④⑤ 在 v1.32 落地（`ChangeDrilldown.tsx` + `lib/change-list.ts` + `FilePreview.tsx`）——「改动」「文件」两个页签**整个取消**，总账与 ④ 工具卡路径都进同一个下钻：`list`（按目录一层分组、同一文件折成 `×N`）→ `diff`（可切历史）→ `content`；三条出口（面包屑 / 层底「返回」/ ESC 逐层回退）。⑤ 的越界过滤统一收在 `buildChangeList` 的 `isProjectRelative`，清单底部如实写「已隐藏 N 个」。层状态由 `ChangeDrilldown` 自己持有，容器只管「在不在下钻」（`drillEntry`），故切页签不丢下钻、换会话即退出。**「计划」那一段与更名都还没落地**——v1.48 只记决定。
- **规则 ⑦-H**：**附属视图给「结论」，不给「流水」。**
  - 流水在别处已有：**④ 消息流的工具卡就是工具调用的叙事流水，且比面板多一个「输出」**；附属视图的价值在**聚合**，不在罗列。

    | 视图 | 聚合内容 | 明细去处 |
    |---|---|---|
    | **统计** | 总额（tokens / 费用）+ **按模型分组**（次数 / tokens / 费用 / 占比）+ **工具调用次数排行** + **工具耗时排行** + 失败统计 | **并入本视图的折叠明细区**（带筛选） |

#### ⑦ 实现约束（用户不可感知，但代码必须遵守）

- **约束 ⑦-1：「不限个数」指的是页签，不是同时挂载的 WebContentsView。** 各视图资源成本差异极大（任务摘要纯 DOM≈0；浏览器 = 一个独立渲染进程，几十到几百 MB）。因此：页签可以很多（只记录状态与位置）；同时存活的重型视图必须限制；超出的应**挂起**（销毁视图、保留页签与 URL，切回时重建）。**现状：限 2~3 个 / 超限挂起从未实现**（并入 `NEXT-PHASE.md` 的「事 B」），别当成已生效。
- **约束 ⑦-2：懒创建必须到页签层，不只是浏览器。** `browser-host.ts` 已是会话级懒创建；接入工作区后应下沉到**视图级**——未激活的页签不创建 `WebContentsView`。
- **约束 ⑦-3：视图销毁必须可回收。** `browser-host.ts` 注释已记录过这个坑：新窗口一律不开——默认行为会生出一个**不受本类管理**的窗口，读不到、`disposeAll` 也回收不掉，而 agent 后续 `snapshot` / `text` 仍停在旧页面上，**表现为「点了没反应」**。任何视图都必须登记在容器里，能随会话 / 页签关闭或挂起而正确销毁，不留孤儿进程。顺序是「摘出视图 → 判活（destroyed 后访问属性会抛）→ 关」。
- **约束 ⑦-4：读文件视图的「根」只能由主进程推导；路径必须落在根内。** 载体已由「文件」页签变更为「任务摘要」下钻的**内容层**（`panels/FilePreview.tsx`），约束本身不变。渲染项目内文件时，根由主进程按 `sessionId → 项目 → root_path` 查出，并做三层校验（`resolve` 后仍须落在根内 → `realpath` 之后**再判一次** → 大小上限 + 二进制判定）。**绝不能让渲染层指定读哪个根**——渲染层会渲染 agent 生成的 Markdown，一旦放开等于把任意读盘能力交出去。路径**相对 / 绝对皆收**（工具入参里的 path 由模型给出，可能是绝对路径），但都必须落在根内；**越界判断是纯字符串运算，先于任何 fs 访问**——根外的绝对路径不会去碰磁盘，因此不会变成「某路径存不存在」的探测口。实现见 `src/main/file-read.ts`。另注：`sessions` 表**不存 cwd**，根只在 `projects.root_path` 上。

## 三、归属判定速查表

新增功能时，按顺序自问：

| 问题 | 归属 |
|---|---|
| 它是操作系统层面的窗口操作吗 | ① |
| 它是**关于会话本身**的操作，且会话不运行时也成立吗 | ② |
| 它是**跨会话 / 跨项目的导航**吗 | ③ |
| 它是**对话过程的一部分**，需按时间出现在叙事里吗 | ④ |
| 它是**发送消息的参数**或**控制本次运行**吗 | ⑤ |
| 它只是**观测**运行状态吗 | ⑥ |
| 它是**agent 动作对象的投影**（页面 / 文件）吗 | ⑦ |

**都不符合 → 不要加**，而不是「找个地方塞进去」。
